## Prerequisites

| Tool | Version |
|------|---------|
| Node.js | 24 |
| pnpm | 10.6.0 |
| Docker | any recent version (for RustFS storage) |
| `just` | any recent version (task runner) |

Install `just` from [https://github.com/casey/just](https://github.com/casey/just) or your system package manager.

---

## Quick Setup

```bash
# 1. Fork the repo on GitHub, then clone your fork
git clone https://github.com/your-username/ouitransfer
cd ouitransfer

# 2. Install deps + generate Prisma client + create local SQLite DB
just setup-dev

# 3. Start all apps in development mode
just dev
```

Running services:
- **API** (Fastify): http://localhost:3333
- **Web** (Next.js): http://localhost:3000
- **Docs** (Fumadocs): http://localhost:3001

**No S3 setup required.** The server starts without storage. Auth, config, and the UI all work. File operations are unavailable until you connect S3 (see `apps/server/.env.development` for the local RustFS config). Dev secrets (`JWT_SECRET` etc.) are committed in `.env.development` files, so no manual configuration is needed.

## Development Tools

### Linting & Formatting

[**Biome**](https://biomejs.dev/) handles both linting and formatting (replaces ESLint + Prettier). [**Lefthook**](https://github.com/evilmartians/lefthook) runs Biome automatically on staged files before every commit; no manual formatting needed.

```bash
just lint                      # Check all files
pnpm biome check --write .     # Auto-fix
```

### Testing

- **Unit / integration**: [Vitest](https://vitest.dev/): `just test`
- **E2E**: [Playwright](https://playwright.dev/): `pnpm e2e` (requires running dev server)

### `just` Recipes

Run `just --list` to see everything. The most common ones:

| Command | Description |
|---------|-------------|
| `just setup-dev` | First-time local dev setup |
| `just dev` | Start all apps in watch mode |
| `just test` | Run all Vitest tests |
| `just lint` | Run Biome across the monorepo |
| `just validate` | type-check + lint + test (full CI check) |
| `just db-generate` | Re-generate Prisma client after schema changes |
| `just db-dev-init` | (Re-)create local SQLite DB |
| `just db-migrate-dev` | Apply pending migrations |
| `just db-seed` | Seed the database |

### Build Orchestration

[**Turborepo**](https://turborepo.com/) manages the build pipeline across `apps/` and `packages/`. Always run `pnpm install` and build commands from the **repo root**, not from individual app directories.

## Commit Format

Commits are enforced by **commitlint** (via Lefthook) using the [Conventional Commits](https://www.conventionalcommits.org/) specification:

```
<type>(<scope>): <description>
```

Both **type** and **scope** are required and must be from the allowed lists; the commit is rejected otherwise. See [Repository Structure → Commit message format](/docs/v1-beta/github-architecture#commit-message-format) for the full reference.

Examples:
```
feat(server): add password-protected share expiry
fix(web): correct token refresh cookie path
docs(docs): update manual installation guide
chore(deps): update Fastify to v5.3
```

## Submitting a Pull Request

1. Create a branch from `main`: `git checkout -b fix/your-branch-name upstream/main`
2. Make atomic, conventional commits
3. Run `just validate`: must pass before opening a PR
4. Open a PR against the `main` branch of `slvnlrt/ouitransfer`
5. Fill in the PR template with what changed and why

Keep PRs focused: one concern per PR makes review faster. See [GitHub's pull request docs](https://docs.github.com/en/pull-requests) for the mechanics of forking and opening PRs.

---

## Branch Naming

Use descriptive names following this pattern:

- `feature/user-authentication`: new features
- `fix/login-bug`: bug fixes
- `docs/api-documentation`: documentation updates
- `refactor/database-queries`: code improvements
