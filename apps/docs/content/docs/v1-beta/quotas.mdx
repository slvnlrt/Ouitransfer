Storage quotas control how much data each user can store and the maximum size of individual files they can upload. Ouitransfer enforces two independent limits per user: a **max file size** cap on any single uploaded file, and a **max total storage** cap on the user's cumulative stored data.

## Overview

Ouitransfer uses a two-level quota system:

- **Global defaults**: configured on the Settings page. These apply to all regular users who have no personal or group override.
- **Per-user overrides**: set per user in User Management. These take priority over global defaults for that specific user.
- **Group-level inheritance**: a user can belong to a Group that carries its own quota overrides, which sit between per-user overrides and global defaults. See the [Groups](/docs/v1-beta/groups) page for details.

Admins are exempt from global defaults by design. Unless you explicitly set an override on an admin account, admins have unlimited storage and file size.

## How quota resolution works

When a user initiates an upload, the server resolves that user's effective limits using the following priority chain:

```
Per-user override  →  Group override  →  Global default
```

The first non-`null` value in this chain wins. The resolution applies independently to both limits (max file size and max total storage), so you can override one without the other.

### Special case: admins

Admin accounts default to **unlimited** (no cap) when neither a per-user override nor a group override is set. You can still impose a hard cap on an admin by setting a per-user override explicitly.

### Value semantics

| Value | Meaning |
|-------|---------|
| `null` | No override: inherit from the next level in the chain |
| `0` | Unlimited: no limit enforced |
| `> 0` | Explicit limit in bytes |

BigInt byte values are serialized as strings in API responses.

<Callout type="info">
  The source of each effective limit is visible in the User Edit panel: the UI shows whether a value comes from a per-user override, a group, the global default, or the admin default.
</Callout>

## Global defaults

Navigate to **Admin → Settings** to configure the global defaults:

| Setting | Description |
|---------|-------------|
| **Max File Size** | Maximum size for a single uploaded file, in bytes. Applies to all regular users with no override. |
| **Max Total Storage Per User** | Maximum cumulative storage a single regular user may occupy, in bytes. |

These settings apply to every regular user who does not have a per-user override or a group override. Admin accounts are not affected unless explicitly overridden.

## Per-user overrides

Navigate to **Admin → User Management**, then open a user's **Edit** dialog. The **Quota** section at the bottom of the form lets you configure that user's overrides:

- **Max File Size**: choose **Inherit** (use next level in chain), **Unlimited**, or **Custom** (enter a byte value).
- **Max Total Storage**: same three options.

The form also displays a read-only summary of the user's current effective limits (resolved through the full chain), their current storage usage, and the source of each effective value (user override, group name, global default, or admin default).

Saving the form persists both the profile changes and the quota overrides in a single submit.

<Callout type="warn">
  Setting a per-user override to **Inherit** (`null`) removes the override entirely. The user then falls back to their group's quota, or to the global default if they have no group.
</Callout>

## What counts toward storage

A user's storage total is calculated as:

```
Total = SUM(File.size for files owned by user)
      + SUM(ReverseShareFile.size for reverse shares created by user)
```

Key points:

- Only finalized files recorded in the database are counted. In-progress multipart upload fragments stored on the S3 side are excluded (those are an S3 lifecycle concern, not a quota concern).
- **Shares** are views over existing files and do not count separately. Creating a share does not consume additional storage.
- Files received through a **reverse share** owned by the user *do* count; they are stored under the user's account once accepted.

<Callout type="info">
  To automatically clean up incomplete multipart upload fragments, configure an `AbortIncompleteMultipartUpload` lifecycle policy on your S3-compatible bucket. This is not handled by the application.
</Callout>

## Blocking behavior

| Action | User over quota? | Outcome |
|--------|-----------------|---------|
| Upload a file | Yes | **Blocked**: 400 error with a clear message |
| Upload a file | No | Checked against both max file size and max total storage |
| Create a share | Yes | **Allowed**: shares don't consume new storage |
| Create a reverse share | Yes | **Allowed** (with an in-app warning) |
| Third party uploads to a reverse share | Yes | **Allowed**: external uploaders are never blocked |

The rationale for not blocking third-party uploads to a reverse share: the creator may be over quota, but blocking external clients would break the service contract. The creator's own next direct upload will be blocked, giving them an incentive to free space.

<Callout type="info">
  Quota checks are optimistic. Two simultaneous uploads may each pass the check individually but together exceed the limit. The slight overage is acceptable; the next upload will be blocked. File sizes are typically megabytes while quotas are gigabytes, so overruns are negligible.
</Callout>

## Quota indicator

Every authenticated user sees a **storage usage indicator** in the System Status Bar, the collapsible panel that appears below the navigation bar on the dashboard. Expand it to view the quota details.

The indicator shows:

- Current usage and effective limit with a progress bar (e.g., "5.0 GB / 10.0 GB")
- A progress bar color-coded by warning level:

| Warning level | Threshold | Color |
|--------------|-----------|-------|
| `none` | < 80 % | Default |
| `warning` | 80-89% | Yellow |
| `critical` | 90-99% | Orange |
| `exceeded` | ≥ 100 % | Red |

- If the effective limit is **unlimited** (`0`), the indicator shows current usage only with no progress bar.

When the warning level is `warning` or `critical`, a percentage badge appears on the collapsed System Status Bar tab to draw attention without requiring the panel to be open.

## API reference (admin)

All quota management endpoints require an authenticated admin session. Non-admin requests receive `403 Forbidden`.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/users/:id/quota` | Returns the user's effective limits, current storage usage, warning level, and override values. BigInt fields are returned as strings. |
| `PATCH` | `/users/:id/quota` | Sets per-user quota overrides. Accepts `null` (clear override/inherit), `"0"` (unlimited), or a positive byte value as a number or numeric string. Both fields are optional; omit a field to leave it unchanged. |

### `GET /users/:id/quota`: Response

```json
{
  "used": "5368709120",
  "maxTotalStorage": "10737418240",
  "maxFileSize": "1073741824",
  "percentage": 50,
  "warningLevel": "none",
  "uploadAllowed": true,
  "overrides": {
    "maxFileSizeOverride": null,
    "maxTotalStorageOverride": null
  },
  "sources": {
    "maxFileSizeSource": "global",
    "maxTotalStorageSource": "global",
    "groupName": null
  }
}
```

**`sources`** fields describe where each effective limit comes from:

| Value | Meaning |
|-------|---------|
| `"user"` | Per-user override is set |
| `"group"` | Inherited from the user's group |
| `"global"` | Falling back to the global default |
| `"admin-default"` | Admin account with no override (unlimited) |

### `PATCH /users/:id/quota`: Request body

```json
{
  "maxFileSizeOverride": null,
  "maxTotalStorageOverride": "21474836480"
}
```

Both fields are optional. Send only the fields you want to change.

| Field | Type | Description |
|-------|------|-------------|
| `maxFileSizeOverride` | `number \| string \| null` | `null` = inherit, `0` = unlimited, `> 0` = limit in bytes. Max value: 1 PB. |
| `maxTotalStorageOverride` | `number \| string \| null` | Same semantics as above. |

**Response:**

```json
{
  "message": "User quota overrides updated",
  "overrides": {
    "maxFileSizeOverride": null,
    "maxTotalStorageOverride": "21474836480"
  }
}
```
