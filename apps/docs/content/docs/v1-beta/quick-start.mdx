This guide takes you from zero to a running OUITRANSFER instance in about 5 minutes. By the end, you'll have the web interface available at **`http://YOUR_IP:5487`**, with storage, the API, and the frontend all running and talking to each other.

## Prerequisites

Before you begin, make sure you have:

- **Docker**: Container runtime ([installation guide](https://docs.docker.com/get-docker/))
- **Docker Compose**: Multi-container orchestration ([installation guide](https://docs.docker.com/compose/install/))
- **2 GB+ available disk space** for the application and your files

**Ports you'll need available:**
- **5487**: Web interface (required)
- **9000**: Storage service. Browsers upload and download files directly to this port when using the built-in storage. Not needed if you use an external S3 provider or a reverse proxy that exposes storage on a domain.
- **3333**: API server, internal only. Only expose it if you want direct access to the API or its documentation.

<Callout>
  **Platform Support**: Thanks to Docker's containerized architecture, OUITRANSFER can be deployed on
  any platform that supports Docker: Linux, macOS, Windows, NAS devices, and cloud VMs alike. For
  those unfamiliar with Docker: it packages the entire application and its dependencies into isolated
  containers, so the host operating system matters very little. That said, **a Linux server is
  recommended for production** deployments, offering better I/O performance, lower overhead, and
  more predictable behavior for long-running container workloads.
</Callout>

## How it Works

OUITRANSFER runs as three Docker containers that start in sequence:

| Service | Image | Port | Description |
|---------|-------|------|-------------|
| **storage** | `rustfs/rustfs:latest` | 9000 | S3-compatible object storage (RustFS) |
| **server** | `ghcr.io/slvnlrt/ouitransfer-server:latest` | 3333 | Fastify API server |
| **web** | `ghcr.io/slvnlrt/ouitransfer-web:latest` | 5487 | Next.js web frontend |

Docker Compose manages the startup order automatically: storage starts first, then the server (once storage is healthy), then the web frontend (once the server is healthy). On first start, the server creates the database and seeds initial configuration automatically.

## Step 1: Generate Your Secrets

OUITRANSFER requires four independent cryptographic secrets. Run this command four separate times and save each output:

```bash
openssl rand -hex 32
```

You'll use the four values as `JWT_SECRET`, `CSRF_SECRET`, `COOKIE_SECRET`, and `ENCRYPTION_SECRET` in the next step. They **must all be different** from each other. The server refuses to boot in production on a known placeholder or low-entropy value.

<Callout type="warn">
  Do not reuse the same value for multiple secrets. Each must be unique.
</Callout>

## Step 2: Configure Your Environment

Create a `.env` file from the provided example:

```bash
cp .env.docker.example .env
```

Open `.env` in a text editor and fill in the following values:

```bash
# ── Public URLs ───────────────────────────────────────────────────────────────
# These must be URLs that the user's BROWSER can actually reach.
# "localhost" only works when the browser runs on the same machine as Docker.

# Where users open the app. Used for CORS on both the API and the storage service.
FRONTEND_ORIGIN=http://192.168.1.100:5487

# Where browsers upload and download files (direct S3 access via presigned URLs).
# In most setups, same IP as above but on port 9000.
STORAGE_PUBLIC_URL=http://192.168.1.100:9000

# ── S3 Storage Credentials ────────────────────────────────────────────────────
# Shared between the RustFS storage container and the API server.
# Not user-facing - choose any string, just keep them consistent between the two.
S3_ACCESS_KEY=my-access-key
S3_SECRET_KEY=my-secret-key

# ── Security Secrets ──────────────────────────────────────────────────────────
# Paste the four values generated in Step 1. All four must be distinct.
JWT_SECRET=<first openssl output>
CSRF_SECRET=<second openssl output>
COOKIE_SECRET=<third openssl output>
ENCRYPTION_SECRET=<fourth openssl output>
```

<Callout type="info">
  **Running on the same machine?** If your browser and Docker are on the same host, use `localhost`:
  ```bash
  FRONTEND_ORIGIN=http://localhost:5487
  STORAGE_PUBLIC_URL=http://localhost:9000
  ```
</Callout>

<Callout type="info">
  **Why two URL variables?** OUITRANSFER generates presigned URLs, short-lived signed URLs that
  browsers use to upload and download files **directly** from the storage service, bypassing the API
  server. Both variables must be addresses the **user's browser can reach**, not internal Docker
  hostnames like `server:3333` or `storage:9000`.

  Each variable propagates to two internal env vars in the Docker Compose file:
  - `FRONTEND_ORIGIN` → `CORS_ORIGINS` on the API server + `RUSTFS_CORS_ALLOWED_ORIGINS` on storage
  - `STORAGE_PUBLIC_URL` → `STORAGE_URL` on the API server (embedded in presigned URLs) + `CSP_STORAGE_ORIGINS` on the web container

  For a detailed explanation, including reverse proxy setups where storage runs behind a domain, see
  [URL Configuration](/docs/v1-beta/reverse-proxy-configuration#url-configuration).
</Callout>

## Step 3: Create Your docker-compose.yml

Create a `docker-compose.yml` file in the same directory as your `.env`:

```yaml
services:
  # ─── S3-Compatible Object Storage ────────────────────────────
  storage:
    image: rustfs/rustfs:latest
    container_name: ouitransfer-storage
    environment:
      RUSTFS_VOLUMES: /data
      RUSTFS_ACCESS_KEY: "${S3_ACCESS_KEY}"
      RUSTFS_SECRET_KEY: "${S3_SECRET_KEY}"
      RUSTFS_CONSOLE_ENABLE: "false"   # admin console off by default
      RUSTFS_CORS_ALLOWED_ORIGINS: "${FRONTEND_ORIGIN}"
    volumes:
      - storage_data:/data
    ports:
      # The S3 API must be browser-reachable for uploads, so it is published here
      # (works for browsers on your LAN). For an INTERNET-FACING deployment, do not
      # expose :9000 directly — bind it to 127.0.0.1 and front it with a
      # reverse-proxied bucket path (see Reverse Proxy Configuration).
      - "9000:9000"
    healthcheck:
      test: ["CMD-SHELL", "curl -fs http://localhost:9000/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s
    restart: unless-stopped

  # ─── Fastify API Server ──────────────────────────────────────
  server:
    image: ghcr.io/slvnlrt/ouitransfer-server:latest
    container_name: ouitransfer-server
    environment:
      S3_ENDPOINT: storage       # Docker service name - do not change
      S3_PORT: "9000"
      S3_USE_SSL: "false"
      S3_ACCESS_KEY: "${S3_ACCESS_KEY}"
      S3_SECRET_KEY: "${S3_SECRET_KEY}"
      S3_BUCKET_NAME: ouitransfer-files
      S3_REGION: auto
      S3_FORCE_PATH_STYLE: "true"
      STORAGE_URL: "${STORAGE_PUBLIC_URL}"
      JWT_SECRET: "${JWT_SECRET}"
      CSRF_SECRET: "${CSRF_SECRET}"
      COOKIE_SECRET: "${COOKIE_SECRET}"
      ENCRYPTION_SECRET: "${ENCRYPTION_SECRET}"
      CORS_ORIGINS: "${FRONTEND_ORIGIN}"
    volumes:
      - server_data:/app/server
    ports:
      - "3333:3333"              # Optional: remove if you don't need direct API access
    depends_on:
      storage:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3333/health"]
      interval: 15s
      timeout: 5s
      retries: 3
      start_period: 30s
    restart: unless-stopped

  # ─── Next.js Web Frontend ────────────────────────────────────
  web:
    image: ghcr.io/slvnlrt/ouitransfer-web:latest
    container_name: ouitransfer-web
    environment:
      API_BASE_URL: "http://server:3333"   # Internal Docker network - do not change
      JWT_SECRET: "${JWT_SECRET}"
      CSP_STORAGE_ORIGINS: "${STORAGE_PUBLIC_URL}"
    ports:
      - "5487:5487"
    depends_on:
      server:
        condition: service_healthy
    restart: unless-stopped

volumes:
  storage_data:
  server_data:
```

This configuration uses **Docker-managed named volumes** for storage and server data, the recommended approach for most deployments. Docker handles permissions automatically and I/O performance is optimal.

<Callout type="info">
  **Need direct access to data files on your host filesystem?** (e.g. NAS, manual backups, bind
  mount workflows) See the [Bind Mounts](#bind-mounts) section at the bottom of this page.
</Callout>

---

## Step 4: Start OUITRANSFER

```bash
docker compose up -d
```

Docker pulls the images on first run (a few hundred MB, which may take a minute depending on your connection). To watch the startup logs in real time:

```bash
docker compose logs -f
```

Wait until the server logs show `Fastify server listening`. The first startup also runs database migrations and seeds the initial app configuration automatically. No manual steps needed.

## Step 5: Access and First Setup

Open your browser and go to:

```
http://YOUR_IP:5487
```

Replace `YOUR_IP` with the value you used in `FRONTEND_ORIGIN` (or `localhost` if running locally).

**Creating your admin account:**

On a fresh install you'll see the login page. Click **Register** to create the first account. The first registered user is automatically granted **administrator privileges**.

<Callout type="warn">
  **Register right away.** If your instance is reachable from a local network or the internet,
  create your admin account immediately after first start to prevent anyone else from claiming
  administrator access.
</Callout>

Once logged in, explore the **Settings** panel (accessible from the profile menu in the top-right corner) to configure your instance.

## After First Login: Recommended Setup

### Personalize your instance

Go to **Settings → General** to set your application name, logo, and description. These appear throughout the UI and in notification emails.

### Configure email (strongly recommended)

Go to **Settings → Email** to configure an SMTP server. This enables:
- **Password reset**: users who forget their password can recover their account by email.
- **Share notifications**: recipients get an email when a file is shared with them.

Without SMTP, users who lose access to their account cannot recover it without admin intervention.

See [Configuring SMTP](/docs/v1-beta/configuring-smtp) for step-by-step instructions.

If you can't configure SMTP right now, see [Password Reset Without SMTP](/docs/v1-beta/password-reset-without-smtp) for the admin-based workaround.

### Going to production with HTTPS?

If you're deploying behind a reverse proxy (Traefik, Nginx, Caddy) with HTTPS:

1. Add `SECURE_SITE=true` to the **server** service's environment variables in your `docker-compose.yml`. This tells the API to issue cookies with the `Secure` flag, which is required for cookies to work over HTTPS.
2. Set `FRONTEND_ORIGIN` and `STORAGE_PUBLIC_URL` to your `https://` URLs.
3. Configure your reverse proxy to forward requests to the correct containers.

See [Reverse Proxy Configuration](/docs/v1-beta/reverse-proxy-configuration) for a complete guide.

## Bind Mounts

If you need the data files to live at a known path on your host filesystem (useful for NAS setups, bind-aware backup tools, or manual inspection), replace the named volumes in your `docker-compose.yml`:

```yaml
# Replace this in the storage service:
volumes:
  - ./storage-data:/data

# Replace this in the server service:
volumes:
  - ./server-data:/app/server

# Remove the top-level volumes: block entirely (or remove unused entries).
```

<Callout type="warn">
  **Storage permissions**: RustFS runs as UID 10001. Pre-create the directory with correct ownership:
  ```bash
  mkdir -p storage-data
  chown -R 10001:10001 storage-data
  ```
  For server data permissions (SQLite, uploads), see [UID/GID Configuration](/docs/v1-beta/uid-gid-configuration).
</Callout>

## Configuration Reference

### `.env`: Required Variables

| Variable | Description |
|----------|-------------|
| `FRONTEND_ORIGIN` | URL where users access the web interface (e.g. `http://192.168.1.100:5487`). Used for CORS on the API and the storage service. |
| `STORAGE_PUBLIC_URL` | URL where browsers reach the storage service (e.g. `http://192.168.1.100:9000`). Used to generate presigned URLs and configure the Content Security Policy. |
| `S3_ACCESS_KEY` | S3 access key shared between RustFS and the API server. |
| `S3_SECRET_KEY` | S3 secret key shared between RustFS and the API server. |
| `JWT_SECRET` | JWT signing key: at least 32 characters. Generate with `openssl rand -hex 32`. |
| `CSRF_SECRET` | CSRF HMAC key: at least 32 characters, must differ from `JWT_SECRET`. |
| `COOKIE_SECRET` | Cookie signing key: at least 32 characters, must differ from the other two. |
| `ENCRYPTION_SECRET` | AES-256-GCM key for encrypting sensitive data at rest (2FA TOTP secret, LDAP bind password): at least 32 characters, must differ from the other three. Generate with `openssl rand -hex 32`. |

### `.env`: Optional Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `SECURE_SITE` | `false` | Set `true` when serving over HTTPS behind a reverse proxy. Required for cookies to work correctly with HTTPS. |
| `OUITRANSFER_UID` | `1001` | User ID for server container processes. Useful for NAS or bind-mount setups. |
| `OUITRANSFER_GID` | `1001` | Group ID for server container processes. |
| `DEFAULT_LANGUAGE` | `en-US` | Default UI language. See [available languages](/docs/v1-beta/available-languages). |
| `ENABLE_API_DOCS` | `false` | When `true`, exposes the `/swagger` and `/docs` UIs (publicly reachable — no auth gate). Enabling it serves the full OpenAPI spec, so it is **not recommended for internet-facing deployments**. |
| `PRESIGNED_URL_EXPIRATION` | `3600` | Upload presigned URL expiry in seconds (default: 1 hour). |
| `PRESIGNED_GET_URL_EXPIRATION` | `900` | Download presigned URL expiry in seconds (default: 15 min). |
| `TRUST_PROXY` | `loopback` | Fastify trusted proxy setting. Use `loopback` for direct deployments; set your proxy IP when behind a reverse proxy. |
| `OAUTH_ALLOWED_REDIRECT_HOSTS` | None | Comma-separated additional redirect hosts for custom OIDC providers. |

### Fixed Variables (set in docker-compose.yml)

These are set directly in `docker-compose.yml` and do not normally need to change:

| Variable | Value | Description |
|----------|-------|-------------|
| `S3_ENDPOINT` | `storage` | Docker service name for internal storage (do not change). |
| `S3_PORT` | `9000` | Internal storage port. |
| `S3_USE_SSL` | `false` | No TLS on the internal Docker network. |
| `S3_BUCKET_NAME` | `ouitransfer-files` | Bucket name created at startup. |
| `API_BASE_URL` | `http://server:3333` | Internal API URL, uses Docker service name (do not change). |

## Maintenance

### Updates

```bash
docker compose pull
docker compose up -d
```

Database migrations and seed updates run automatically on startup. No manual migration steps needed.

### Check Status

```bash
# Container status and health
docker compose ps

docker compose logs -f

# API health endpoint (if port 3333 is exposed)
```
