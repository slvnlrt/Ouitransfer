The Ouitransfer API is a REST API built with Fastify 5, Zod, and TypeScript. It powers all operations in the platform — the web frontend communicates with it through a proxy layer, but you can also call it directly for automation, integrations, or custom clients.

## Base URL

The API server runs on port **3333** by default. For direct API access, use the server URL:

```
http://your-server:3333
```

<Callout type="info">
  The Next.js web app proxies most API requests through its own `/api/[...proxy]` route. For direct API access (scripts, CI/CD, custom clients), always target the server URL, not the web app URL.
</Callout>

To expose the API port in Docker Compose, add `ports: ["3333:3333"]` to the `server` service. See the [Quick Start guide](/docs/v1-beta/quick-start) for a full deployment example.

## Authentication

The API uses **httpOnly signed cookies** for authentication — there is no API key system. Authenticate by calling the login endpoint, then include the returned cookies in subsequent requests.

### Login flow

1. **Get a CSRF token** — `GET /csrf-token` returns a `token` value and sets a `_csrf` cookie.
2. **Login** — `POST /auth/login` with credentials. On success, the server sets `token` (JWT access token) and `refreshToken` cookies.
3. **Make requests** — include cookies on all subsequent requests. The JWT is short-lived (15 minutes); use `POST /auth/refresh` to obtain a new one.

### CSRF protection

All **mutating requests** (POST, PUT, PATCH, DELETE) require a CSRF token, unless the endpoint is explicitly exempt. Ouitransfer uses the **double-submit cookie** pattern:

- The `_csrf` cookie contains a secret set by the server.
- The client must send a matching token in the `X-CSRF-Token` request header.
- Obtain the token from `GET /csrf-token`.
- GET, HEAD, and OPTIONS requests do not require the CSRF header.

**CSRF-exempt endpoints** (public or unauthenticated mutations): `/auth/login`, `/auth/refresh`, `/auth/forgot-password`, `/auth/reset-password`, `/auth/2fa/login`, `/register-with-invite`, share and reverse share password-access endpoints, and all reverse share public upload endpoints.

### Example: curl login

```bash
# 1. Get CSRF token
CSRF=$(curl -s -c cookies.txt http://localhost:3333/csrf-token | jq -r '.token')

# 2. Login
curl -s -b cookies.txt -c cookies.txt \
  -H "Content-Type: application/json" \
  -H "X-CSRF-Token: $CSRF" \
  -d '{"emailOrUsername":"admin@example.com","password":"yourpassword"}' \
  http://localhost:3333/auth/login

# 3. Make authenticated requests (cookies are sent automatically)
curl -s -b cookies.txt http://localhost:3333/files
```

## Interactive documentation

When API docs are enabled (always in development, opt-in in production via `ENABLE_API_DOCS=true`), two interactive documentation UIs are available:

- **Scalar** — `http://localhost:3333/docs`
- **Swagger UI** — `http://localhost:3333/swagger`

Both provide endpoint exploration, request builders, and response visualization generated from the Zod schemas.

## Endpoint reference

### Authentication

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/login` | — | Login with email/username and password |
| POST | `/auth/2fa/login` | — | Complete login with 2FA verification code |
| POST | `/auth/logout` | — | Logout and clear session cookies |
| GET | `/auth/me` | — | Get current authenticated user (returns `null` if not logged in) |
| POST | `/auth/forgot-password` | — | Request password reset email |
| POST | `/auth/reset-password` | — | Reset password using token from email |
| POST | `/auth/refresh` | — | Refresh access token using refresh token cookie |
| GET | `/auth/config` | — | Get auth configuration (whether password auth is enabled) |
| GET | `/auth/trusted-devices` | User | List trusted 2FA devices |
| DELETE | `/auth/trusted-devices/:id` | User | Remove a specific trusted device |
| DELETE | `/auth/trusted-devices` | User | Remove all trusted devices |
| GET | `/csrf-token` | — | Get a CSRF token (sets `_csrf` cookie) |

**Login** returns the user object on success. If the account has 2FA enabled, it returns `{ requiresTwoFactor: true, challengeToken: "..." }` — pass the challenge token and TOTP code to `/auth/2fa/login` to complete authentication.

**Rate limits:** Login: 5 attempts per minute per IP. Forgot password: 3 per minute per IP. Reset password: 3 per minute per IP. Token refresh: 10 per minute per IP.

## Common response codes

| Code | Meaning |
|------|---------|
| 200 | OK — request succeeded |
| 201 | Created — resource created successfully |
| 302 | Redirect — OAuth/OIDC flow redirects |
| 400 | Bad Request — validation failure (Zod schema) |
| 401 | Unauthorized — not authenticated, invalid token, or CSRF mismatch |
| 403 | Forbidden — authenticated but insufficient permissions |
| 404 | Not Found — resource does not exist |
| 409 | Conflict — duplicate resource or file-in-shares conflict |
| 410 | Gone — share or reverse share has expired |
| 413 | Payload Too Large — file exceeds quota |
| 429 | Too Many Requests — rate limit exceeded |
| 500 | Internal Server Error |

All error responses follow a consistent JSON shape:

```json
{
  "error": "ERROR_CODE",
  "message": "Human-readable description",
  "statusCode": 400
}
```

## Rate limiting

Global rate limit: **100 requests per minute per IP**. Individual endpoints may impose stricter limits:

| Endpoint | Limit |
|----------|-------|
| `POST /auth/login` | 5 / minute |
| `POST /auth/2fa/login` | 5 / minute |
| `POST /auth/forgot-password` | 3 / minute |
| `POST /auth/reset-password` | 3 / minute |
| `POST /auth/refresh` | 10 / minute |
| `POST /auth/2fa/verify` | 5 / minute |
| `GET /files/presigned-url` | 30 / minute |
| `POST /files/download-url` | 20 / minute |
| `POST /files/download` | 20 / minute |
| `POST /s3/upload-url` | 30 / minute |
| `GET /csrf-token` | 30 / minute |

When rate-limited, the server returns `429 Too Many Requests` with a `retryAfter` field indicating seconds until the limit resets.
