Found a bug, have a feature request, or need clarification? Open an issue on GitHub. It's the best way to get visibility from maintainers and the community.

The repository is at: [github.com/slvnlrt/ouitransfer](https://github.com/slvnlrt/ouitransfer)

---

## Before opening an issue

- **Search first**: check if the issue already exists (open and closed). Avoid duplicates.
- **Gather details**: collect error messages, logs, steps to reproduce, and your environment (OS, Docker version, browser).

---

## Bug reports

Include:

- **Steps to reproduce**: numbered, minimal, and reliable
- **Expected behavior** vs. **actual behavior**
- **Environment**: OS, Docker version, browser (if applicable), Ouitransfer version
- **Logs**: server logs (`docker compose logs server`), browser console errors
- **Screenshots**: if the issue is visual

<Callout type="info">
  For authentication or storage issues, check `docker compose logs server` first; the server logs usually contain the root cause.
</Callout>

---

## Feature requests

Include:

- What you want to do and why
- How you currently work around the limitation (if any)
- Any implementation ideas you have (optional)

---

## Writing a good title

Use a concise, descriptive title that summarizes the problem:

- `File upload fails silently when storage quota is exceeded`: good
- `Bug` or `Problem with files`: not useful

---

## After submitting

Monitor your issue for follow-up questions. Maintainers may ask for additional details or clarifications. Responding promptly speeds up resolution.

[Open an issue on GitHub →](https://github.com/slvnlrt/ouitransfer/issues/new/choose)
