Ce guide fournit des instructions détaillées pour réinitialiser un mot de passe utilisateur directement à l'intérieur du conteneur Docker OUITRANSFER, sans nécessiter de configuration SMTP. Cette méthode est particulièrement utile pour les administrateurs qui n'ont pas de services e-mail configurés ou qui ont besoin de retrouver l'accès à des comptes dans des situations d'urgence.

> **Remarque :** Ces commandes ciblent le conteneur **server** (`ouitransfer-server`). Dans l'architecture à 3 conteneurs, le serveur API est le service qui gère les comptes utilisateurs et l'accès à la base de données.

## Quand et pourquoi utiliser cette méthode

La réinitialisation d'un mot de passe sans SMTP est une approche alternative pour des scénarios spécifiques où la réinitialisation standard par e-mail n'est pas réalisable. Envisagez cette méthode si :

- Un utilisateur admin est bloqué et ne peut pas accéder à son e-mail pour réinitialiser son mot de passe.
- Les services SMTP ne sont pas configurés ou rencontrent des problèmes.
- Vous devez effectuer une récupération d'urgence du système et rétablir l'accès rapidement.
- Vous configurez un environnement initial et devez paramétrer des comptes.
- Vous effectuez des tests contrôlés dans un environnement de développement.

> **Avertissement :** Ce processus contourne le mécanisme normal de réinitialisation de mot de passe par e-mail, ce qui peut présenter un risque de sécurité s'il n'est pas géré correctement. N'utilisez cette méthode que lorsque cela est nécessaire, assurez-vous qu'elle est effectuée par des administrateurs de confiance et documentez toujours la raison de la réinitialisation.

## Fonctionnement de la réinitialisation du mot de passe

OUITRANSFER fournit un script CLI qui permet aux administrateurs de réinitialiser les mots de passe directement dans le conteneur Docker. Ce script est conçu pour maintenir la sécurité en imposant une confirmation interactive à chaque étape, en validant les données saisies et en chiffrant le nouveau mot de passe de manière sécurisée avec bcrypt et 10 tours de salage (conformément aux standards de sécurité du système). Le script n'envoie pas de notifications par e-mail, n'enregistre pas les tentatives de connexion invalides et ne modifie pas les autres paramètres utilisateur — il se concentre uniquement sur la réinitialisation du mot de passe.

## Instructions étape par étape

Suivez ces étapes pour réinitialiser un mot de passe utilisateur à l'aide du script fourni. Assurez-vous d'avoir accès au conteneur Docker avant de commencer.

### 1. Lister les conteneurs Docker et identifier le bon

Avant d'accéder au conteneur server, vous devez identifier son nom ou son ID. Ouvrez un terminal sur votre machine hôte et listez tous les conteneurs Docker en cours d'exécution avec la commande suivante :

```bash
docker ps
```

Cette commande affiche la liste des conteneurs actifs, y compris leurs noms, IDs, images et autres détails. Recherchez le conteneur exécutant le serveur OUITRANSFER. Si vous avez utilisé la configuration Docker Compose par défaut, il sera nommé `ouitransfer-server` dans la colonne `NAMES`.

> **Remarque :** Si vous ne voyez pas le conteneur `ouitransfer-server`, assurez-vous qu'il est en cours d'exécution. Vous pouvez le démarrer avec `docker compose up -d server` depuis votre répertoire Docker Compose. Si vous n'êtes pas sûr de la configuration, consultez le guide d'installation d'OUITRANSFER.

### 2. Accéder au conteneur Docker

Une fois le conteneur correct identifié, accédez-y avec la commande suivante :

```bash
docker exec -it ouitransfer-server /bin/sh
```

Cette commande ouvre une session shell interactive à l'intérieur du conteneur server, vous permettant d'exécuter des commandes directement.

### 3. Naviguer vers le répertoire de l'application

Une fois à l'intérieur du conteneur, naviguez vers le répertoire de l'application où se trouve le script de réinitialisation :

```bash
cd /app/ouitransfer-app
```

Ce répertoire contient les scripts et configurations nécessaires à la gestion des opérations backend d'OUITRANSFER.

### 4. Exécuter le script de réinitialisation du mot de passe

Exécutez le script de réinitialisation du mot de passe pour démarrer le processus interactif :

```bash
./reset-password.sh
```

Le script vous demandera de saisir l'adresse e-mail de l'utilisateur dont vous souhaitez réinitialiser le mot de passe. Il affichera ensuite les informations de l'utilisateur pour vérification, demandera une confirmation pour continuer, puis sollicitera un nouveau mot de passe (minimum 8 caractères) qui devra être saisi deux fois pour garantir l'exactitude. Chaque étape requiert une confirmation explicite afin d'éviter les modifications accidentelles.

> **Remarque :** Si vous souhaitez consulter la liste de tous les utilisateurs du système avant de procéder, vous pouvez exécuter `./reset-password.sh --list`. Pour obtenir de l'aide supplémentaire, utilisez `./reset-password.sh --help`.

## Résolution des problèmes courants

Si vous rencontrez des difficultés lors de l'exécution du script, consultez les solutions suivantes pour résoudre les problèmes courants :

- **Erreur : « tsx is not available »**  
  Cette erreur indique des dépendances manquantes. Le script tentera de les installer automatiquement, mais en cas d'échec, installez-les manuellement avec :

  ```bash
  pnpm install
  ```

- **Erreur : « Prisma client not found »**  
  Cette erreur se produit si le client Prisma n'est pas généré. Le script devrait gérer cela automatiquement, mais en cas d'échec, générez-le manuellement avec :

  ```bash
  pnpm --filter ouitransfer-api exec prisma generate
  ```

  Remarque : Prisma 7 lit `prisma.config.ts` depuis le répertoire du package server (`apps/server/`). L'exécution de `prisma generate` depuis la racine du dépôt ne trouvera pas la configuration — utilisez l'option `--filter` indiquée ci-dessus, ou `cd apps/server && pnpm exec prisma generate`.

- **Erreur : « Database connection failed »**  
   Si le script ne peut pas se connecter à la base de données, vérifiez les points suivants :
   - Assurez-vous que le service de base de données est en cours d'exécution dans le conteneur.
   - Confirmez que le fichier de base de données `/app/server/prisma/OUITRANSFERdb` existe et possède les permissions correctes.
   - Vérifiez que le conteneur a accès au volume de base de données.

- **Erreur : « Script must be run from application directory »**  
  Cette erreur s'affiche si vous n'êtes pas dans le bon répertoire. Naviguez vers le répertoire de l'application avec :

  ```bash
  cd /app/ouitransfer-app
  ```

- **Erreur : « User not found »**  
  Si l'adresse e-mail fournie ne correspond à aucun utilisateur, vérifiez l'adresse e-mail. Vous pouvez lister tous les utilisateurs pour trouver le bon en exécutant :

  ```bash
  ./reset-password.sh --list
  ```

  Assurez-vous que l'utilisateur existe dans le système avant de tenter la réinitialisation.

- **Erreur : « Password does not meet requirements »**  
  Le nouveau mot de passe doit comporter au moins 8 caractères. Assurez-vous qu'il respecte cette exigence et saisissez-le attentivement, en vérifiant qu'il correspond à la seconde saisie.

- **Erreur : « Confirmation does not match »**  
  Si les deux saisies du mot de passe ne correspondent pas, le script vous invitera à recommencer. Assurez-vous que les deux saisies sont identiques.

- **Échec général du script ou comportement inattendu**  
  Si le script échoue pour une raison inconnue, consultez le message d'erreur pour obtenir des détails. Assurez-vous que votre installation OUITRANSFER est à jour et envisagez de redémarrer le conteneur en cas de problèmes transitoires. Si les problèmes persistent, consultez la documentation ou la communauté OUITRANSFER pour obtenir de l'aide supplémentaire.

## Sécurité et bonnes pratiques

Pour préserver l'intégrité et la sécurité de votre instance OUITRANSFER lors de l'utilisation de cette méthode de réinitialisation du mot de passe, respectez les directives suivantes :

- **Confirmation interactive :** Le script impose le mode interactif, exigeant une confirmation explicite à chaque étape pour éviter les réinitialisations non autorisées ou accidentelles. Il n'existe pas de raccourcis ni d'options automatisées.
- **Restriction d'accès :** Seuls les administrateurs disposant d'un accès direct au conteneur Docker peuvent utiliser ce script, garantissant que les utilisateurs non autorisés ne peuvent pas réinitialiser les mots de passe.
- **Chiffrement du mot de passe :** Les nouveaux mots de passe sont chiffrés avec bcrypt et 10 tours de salage, conformément aux pratiques de sécurité standard d'OUITRANSFER.
- **Documentation et notification :** Documentez toujours la date, l'heure et la raison d'une réinitialisation de mot de passe. Informez l'utilisateur concerné par d'autres moyens (si possible) pour le notifier du changement.
- **Recommandation de sauvegarde :** Avant d'utiliser ce script dans un environnement de production, envisagez de sauvegarder votre base de données pour éviter toute perte de données en cas d'erreur.
- **Actions post-réinitialisation :** Après avoir réinitialisé un mot de passe, vérifiez que l'utilisateur peut se connecter avec succès et consultez les journaux système pour détecter toute activité inhabituelle liée à la réinitialisation.
- **Utilisation limitée :** Utilisez cette méthode avec parcimonie et uniquement dans les situations où la réinitialisation par SMTP n'est pas possible. Elle n'est pas destinée à la gestion courante des mots de passe.
- **Environnement sécurisé :** Assurez-vous que l'accès au conteneur Docker et à la machine hôte est sécurisé par des mots de passe robustes, des permissions restreintes et, si possible, une authentification à deux facteurs pour empêcher tout accès non autorisé aux outils d'administration.

> **Conseil :** Considérez cette méthode comme un dernier recours. Dans la mesure du possible, configurez le SMTP pour activer le processus standard de réinitialisation du mot de passe par e-mail, qui offre un niveau supplémentaire de sécurité et de vérification de l'utilisateur.

## Philosophie de sécurité

Ce script est conçu avec une forte priorité accordée à la sécurité, en privilégiant l'interactivité obligatoire, les confirmations multiples et la validation stricte des données saisies. Il n'existe pas de « modes rapides » ni d'options de contournement — chaque réinitialisation de mot de passe requiert une action soigneuse et délibérée de l'administrateur pour garantir la responsabilité et minimiser les risques.
