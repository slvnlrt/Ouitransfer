Welcome to the fastest way to deploy <span className="font-bold">OUITRANSFER.</span> - your secure, self-hosted file sharing solution. This guide will have you up and running in minutes, whether you're new to self-hosting or an experienced developer.

OUITRANSFER. offers flexible deployment options to match your infrastructure needs. This guide focuses on Docker Compose deployment with 3 services: object storage, API server, and web frontend.

## Prerequisites

Before you begin, make sure you have:

- **Docker** - Container runtime ([installation guide](https://docs.docker.com/get-docker/))
- **Docker Compose** - Multi-container orchestration ([installation guide](https://docs.docker.com/compose/install/))
- **2GB+ available disk space** for the application and your files
- **Port 5487** available for the web interface
- **Port 9000** available for S3-compatible storage (**REQUIRED** unless using external S3)
- **Port 3333** available for API access (optional)

<Callout type="warn">
  **Critical**: Port **9000** is **REQUIRED** for internal storage operations. This port exposes the RustFS S3-compatible storage server. Browsers must be able to reach this port for file uploads and downloads. If you cannot expose this port, you **must** configure external S3 storage using the `ENABLE_S3=true` option.
</Callout>

<Callout>
  **Platform Support**: OUITRANSFER. is developed on macOS and extensively tested on Linux servers. While we haven't formally
  tested other platforms, Docker's cross-platform nature should ensure compatibility. Report any issues on our [GitHub
  repository](https://github.com/burger-cie/ouitransfer/issues).
</Callout>

## Architecture

OUITRANSFER runs as 3 Docker containers:

| Service | Image | Port | Description |
|---------|-------|------|-------------|
| **storage** | `rustfs/rustfs:latest` | 9000 | S3-compatible object storage (RustFS) |
| **server** | `ouitransfer/server:latest` | 3333 | Fastify API server |
| **web** | `ouitransfer/web:latest` | 5487 | Next.js web frontend |

Startup order is managed automatically: storage starts first, then server (once storage is healthy), then web (once server is healthy).

## Storage Options

OUITRANSFER. supports two storage approaches for persistent data:

- **Named Volumes (Recommended)** - Docker-managed storage with optimal performance and no permission issues
- **Bind Mounts** - Direct host filesystem access, ideal for development and direct file management

## Deployment

Before deploying, generate three separate secrets:

```bash
# Run this three times, use a different value for each secret
openssl rand -hex 32
```

Choose your storage method based on your needs:

<Tabs items={['Named Volumes (Recommended)', 'Bind Mounts']}>
  <Tab value="Named Volumes (Recommended)">
    Docker-managed storage that provides the best balance of performance, security, and ease of use:

    - **No Permission Issues**: Docker handles all permission management automatically
    - **Performance**: Optimized for container workloads with better I/O performance
    - **Production Ready**: Recommended for production deployments

    ### Configuration

    Create a `docker-compose.yml` file:

    ```yaml
    services:
      # ─── S3-Compatible Object Storage ────────────────────────────
      storage:
        image: rustfs/rustfs:latest
        container_name: ouitransfer-storage
        environment:
          RUSTFS_VOLUMES: /data
          RUSTFS_ACCESS_KEY: ""    # REQUIRED: set your storage access key
          RUSTFS_SECRET_KEY: ""    # REQUIRED: set your storage secret key
          RUSTFS_CONSOLE_ENABLE: "true"
          # REQUIRED: Allow browsers to upload files directly via presigned URLs.
          # Set to the web frontend origin (must match CORS_ORIGINS).
          RUSTFS_CORS_ALLOWED_ORIGINS: ""  # REQUIRED: e.g., http://localhost:5487 or https://files.example.com
        volumes:
          - storage_data:/data
        ports:
          - "9000:9000"    # S3 API — must be reachable by browsers
        healthcheck:
          test: ["CMD-SHELL", "curl -fs http://localhost:9000/health || exit 1"]
          interval: 10s
          timeout: 5s
          retries: 5
          start_period: 10s
        restart: unless-stopped

      # ─── Fastify API Server ──────────────────────────────────────
      server:
        image: ghcr.io/slvnlrt/ouitransfer-server:latest
        container_name: ouitransfer-server
        environment:
          # Storage connection (must match storage service credentials)
          S3_ENDPOINT: storage
          S3_PORT: "9000"
          S3_USE_SSL: "false"
          S3_ACCESS_KEY: ""              # Must match RUSTFS_ACCESS_KEY
          S3_SECRET_KEY: ""              # Must match RUSTFS_SECRET_KEY
          S3_BUCKET_NAME: ouitransfer-files
          S3_REGION: auto
          S3_FORCE_PATH_STYLE: "true"
          # REQUIRED: public URL where browsers can reach storage
          STORAGE_URL: ""                # REQUIRED: replace with your public URL (e.g., http://192.168.1.100:9000)
          # REQUIRED: security secrets — generate each with: openssl rand -hex 32
          JWT_SECRET: ""                 # REQUIRED: generate with: openssl rand -hex 32
          CSRF_SECRET: ""                # REQUIRED: generate with: openssl rand -hex 32
          COOKIE_SECRET: ""              # REQUIRED: generate with: openssl rand -hex 32
          # REQUIRED: comma-separated list of web frontend origins allowed to make requests
          CORS_ORIGINS: ""               # REQUIRED: e.g., http://localhost:5487 or https://files.example.com
          # ENCRYPTION_SECRET: ""       # Required for LDAP — generate with: openssl rand -hex 32
          # Optional settings:
          # OUITRANSFER_UID: "1000"
          # OUITRANSFER_GID: "1000"
          # SECURE_SITE: "true"
          # PRESIGNED_URL_EXPIRATION: "3600"
          # PRESIGNED_GET_URL_EXPIRATION: "900"
        volumes:
          - server_data:/app/server
        ports:
          - "3333:3333"    # API (optional: only needed for direct API access)
        depends_on:
          storage:
            condition: service_healthy
        healthcheck:
          test: ["CMD", "curl", "-f", "http://localhost:3333/health"]
          interval: 15s
          timeout: 5s
          retries: 3
          start_period: 30s
        restart: unless-stopped

      # ─── Next.js Web Frontend ────────────────────────────────────
      web:
        image: ghcr.io/slvnlrt/ouitransfer-web:latest
        container_name: ouitransfer-web
        environment:
          API_BASE_URL: "http://server:3333"
          JWT_SECRET: ""     # REQUIRED: must match server's JWT_SECRET (used by Edge middleware)
          # REQUIRED: must match server's STORAGE_URL — allows browsers to reach storage for uploads/images
          CSP_STORAGE_ORIGINS: ""    # REQUIRED: same value as STORAGE_URL (e.g., http://192.168.1.100:9000)
          # DEFAULT_LANGUAGE: "en-US"
        ports:
          - "5487:5487"    # Web interface
        depends_on:
          server:
            condition: service_healthy
        restart: unless-stopped

    volumes:
      storage_data:
      server_data:
    ```

    <Callout type="info">
      **Having upload or permission issues?** Add `OUITRANSFER_UID=1000` and `OUITRANSFER_GID=1000` to the server service environment variables. Check our [UID/GID Configuration](/docs/v3-beta/uid-gid-configuration) guide for more details.
    </Callout>

## Configuration

Customize OUITRANSFER's behavior with these environment variables. Most are set on the **server** service; a few are set on the **web** service (noted below).

| Variable | Service | Default | Description |
|----------|---------|---------|-------------|
| `STORAGE_URL` | server | - | **REQUIRED** for internal storage: Public URL where browsers reach the storage service (e.g., `http://192.168.1.100:9000`) |
| `CSP_STORAGE_ORIGINS` | **web** | - | **REQUIRED** for internal storage: Must match `STORAGE_URL`. Allows browsers to connect to storage for file uploads and background images (sets `connect-src` and `img-src` CSP directives). |
| `JWT_SECRET` | server + web | - | **REQUIRED**: JWT signing key (min 32 chars). Generate with: `openssl rand -hex 32`. Must be set on **both** the server and web services. |
| `CSRF_SECRET` | server | - | **REQUIRED**: CSRF token HMAC key (min 32 chars, must differ from JWT_SECRET) |
| `COOKIE_SECRET` | server | - | **REQUIRED**: Cookie signing key (min 32 chars, must differ from other secrets) |
| `CORS_ORIGINS` | server | - | **REQUIRED**: Comma-separated list of web frontend origins allowed to make API requests (e.g., `http://localhost:5487` or `https://files.example.com`) |
| `RUSTFS_CORS_ALLOWED_ORIGINS` | **storage** | - | **REQUIRED** for internal storage: Web frontend origin for direct browser uploads via presigned URLs. Must match `CORS_ORIGINS`. |
| `ENABLE_S3` | server | `false` | Set `true` to use external S3 storage (AWS, Backblaze, etc.) instead of built-in RustFS |
| `S3_ENDPOINT` | server | - | S3 server endpoint (required when using S3) |
| `S3_ACCESS_KEY` | server | - | S3 access key for authentication |
| `S3_SECRET_KEY` | server | - | S3 secret key for authentication |
| `S3_BUCKET_NAME` | server | - | S3 bucket name for file storage |
| `S3_REGION` | server | - | S3 region configuration |
| `S3_USE_SSL` | server | `true` | Enable SSL for S3 connections |
| `S3_FORCE_PATH_STYLE` | server | `false` | Force path-style S3 URLs (set `true` for RustFS or self-hosted S3) |
| `S3_REJECT_UNAUTHORIZED` | server | `true` | Strict SSL certificate validation (set `false` for self-signed certificates) |
| `OUITRANSFER_UID` | server | `1000` | User ID for server container processes (helps with file permissions) |
| `OUITRANSFER_GID` | server | `1000` | Group ID for server container processes (helps with file permissions) |
| `DEFAULT_LANGUAGE` | web | `en-US` | Default application language ([see available languages](/docs/v3-beta/available-languages)) |
| `PRESIGNED_URL_EXPIRATION` | server | `3600` | Upload presigned URL expiration in seconds |
| `PRESIGNED_GET_URL_EXPIRATION` | server | `900` | Download presigned URL expiration in seconds |
| `SECURE_SITE` | server | `false` | Enable secure cookies for HTTPS/reverse proxy deployments |
| `TRUST_PROXY` | server | `loopback` | Trusted proxy setting for Fastify (`loopback`, comma-separated IPs, or `true` for all proxies) |
| `ENCRYPTION_SECRET` | server | - | AES-256-GCM key for encrypting sensitive data at rest (e.g., LDAP bind password). Required if using LDAP. Generate with: `openssl rand -hex 32` |
| `ENABLE_API_DOCS` | server | `false` (prod) | Set `true` to enable Scalar/Swagger API documentation at `/docs` and `/swagger` in production |

<Callout type="info">
  **Storage Architecture**: OUITRANSFER v3.3+ uses a 3-container architecture with RustFS as the S3-compatible storage backend. Port 9000 **must** be accessible from browsers for file operations to work properly when using internal storage.
</Callout>

<Callout>
  **Using a Reverse Proxy?** Set `SECURE_SITE=true` and check our [Reverse Proxy
  Configuration](/docs/v3-beta/reverse-proxy-configuration) guide for proper HTTPS setup.
</Callout>

## Docker CLI Alternative

For simple setups or testing, you can run Docker Compose from the command line. Note that OUITRANSFER requires all three services, so Docker Compose is the recommended approach. If you prefer individual `docker run` commands, you must create a shared Docker network and start each container manually:

```bash
# Create a shared network
docker network create ouitransfer

# Start storage
docker run -d \
  --name ouitransfer-storage \
  --network ouitransfer \
  -e RUSTFS_VOLUMES=/data \
  -e RUSTFS_ACCESS_KEY=your-access-key \
  -e RUSTFS_SECRET_KEY=your-secret-key \
  -e RUSTFS_CORS_ALLOWED_ORIGINS=http://YOUR_SERVER_IP:5487 \
  -p 9000:9000 \
  -v storage_data:/data \
  --restart unless-stopped \
  rustfs/rustfs:latest

# Start server (wait for storage to be healthy first)
docker run -d \
  --name ouitransfer-server \
  --network ouitransfer \
  -e S3_ENDPOINT=ouitransfer-storage \
  -e S3_PORT=9000 \
  -e S3_USE_SSL=false \
  -e S3_ACCESS_KEY=your-access-key \
  -e S3_SECRET_KEY=your-secret-key \
  -e S3_BUCKET_NAME=ouitransfer-files \
  -e S3_REGION=auto \
  -e S3_FORCE_PATH_STYLE=true \
  -e STORAGE_URL=http://YOUR_SERVER_IP:9000 \
  -e JWT_SECRET=your-jwt-secret-at-least-32-chars \
  -e CSRF_SECRET=your-csrf-secret-at-least-32-chars \
  -e COOKIE_SECRET=your-cookie-secret-at-least-32-chars \
  -e CORS_ORIGINS=http://YOUR_SERVER_IP:5487 \
  -p 3333:3333 \
  -v server_data:/app/server \
  --restart unless-stopped \
  ghcr.io/slvnlrt/ouitransfer-server:latest

# Start web (wait for server to be healthy first)
docker run -d \
  --name ouitransfer-web \
  --network ouitransfer \
  -e API_BASE_URL=http://ouitransfer-server:3333 \
  -e JWT_SECRET=your-jwt-secret-at-least-32-chars \
  -e CSP_STORAGE_ORIGINS=http://YOUR_SERVER_IP:9000 \
  -p 5487:5487 \
  --restart unless-stopped \
  ghcr.io/slvnlrt/ouitransfer-web:latest
```

<Callout type="warn">
  **Docker Compose is strongly recommended.** The CLI approach above requires manual health checking and startup ordering. Docker Compose handles this automatically via `depends_on` with healthcheck conditions.
</Callout>

## Common Configuration Options

### Cross-Origin Configuration (REQUIRED)

When using internal storage (the default), browsers upload files directly to the storage service via presigned URLs. This requires **two pairs** of environment variables — one pair identifies the **web frontend origin**, and the other identifies the **storage public URL**:

**Web frontend origin** (where users access the app):
- **`CORS_ORIGINS`** (server) — allows the API server to accept requests from the frontend
- **`RUSTFS_CORS_ALLOWED_ORIGINS`** (storage) — allows the storage service to accept direct uploads from the frontend

**Storage public URL** (where browsers reach the storage):
- **`STORAGE_URL`** (server) — tells the server how to generate presigned URLs that browsers can reach
- **`CSP_STORAGE_ORIGINS`** (web) — configures the Content Security Policy to allow browser connections to storage

```yaml
# Storage service
environment:
  RUSTFS_CORS_ALLOWED_ORIGINS: "http://192.168.1.100:5487"  # Web frontend origin

# Server service
environment:
  STORAGE_URL: "http://192.168.1.100:9000"     # Public storage URL
  CORS_ORIGINS: "http://192.168.1.100:5487"    # Web frontend origin

# Web service
environment:
  CSP_STORAGE_ORIGINS: "http://192.168.1.100:9000"  # Must match STORAGE_URL
```

**Important Notes:**
- **`CORS_ORIGINS` and `RUSTFS_CORS_ALLOWED_ORIGINS` must match** — both are the web frontend origin
- **`STORAGE_URL` and `CSP_STORAGE_ORIGINS` must match** — both are the public storage URL
- **Must include protocol** (`http://` or `https://`)
- **Must include port** unless you're using a reverse proxy
- **Use your actual domain/IP** that clients will access — `localhost` only works when browsers run on the same machine as Docker
- **Not needed if using external S3** (`ENABLE_S3=true`) — the S3 endpoint is used directly and `RUSTFS_CORS_ALLOWED_ORIGINS` does not apply
- **Use HTTPS in production** — HTTP exposes presigned URL signatures and file contents on the wire, and browsers block mixed-content requests if the web app is served over HTTPS

### Presigned URL Expiration

OUITRANSFER. uses temporary URLs (presigned URLs) for secure file access. These URLs expire after a configurable time period to enhance security.

**Default:** Upload: 1 hour (3600s), Download: 15 minutes (900s)

You can customize this for all storage types (internal or S3) by adding:

```yaml
environment:
  PRESIGNED_URL_EXPIRATION: "7200"       # Upload: 2 hours
  PRESIGNED_GET_URL_EXPIRATION: "1800"   # Download: 30 minutes
```

**When to adjust:**

- **Shorter time (900 = 15 min):** Higher security, but users may need to refresh download links
- **Longer time (7200-21600 = 2-6 hours):** Better for large file transfers, but URLs stay valid longer
- **Default:** Good balance for most use cases
