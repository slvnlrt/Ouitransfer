# 5.4 — Groups

**Status**: Spec
**Depends on**: 5.1 (Quotas)
**Blocks**: 5.3 (LDAP needs groups to map AD groups → app groups)

---

## Goal

Organizational groups with per-member quota inheritance. Full standalone feature usable with local accounts, designed to be LDAP-ready for future 5.3 integration.

## Decisions

| Question | Decision | Rationale |
|----------|----------|-----------|
| One group or many per user? | **One** — FK `groupId` on User | Simpler model. For LDAP: at sync time, the first matching AD group mapping wins. Users should belong to one resource group in AD; if they have multiple, that's an AD issue, not ours. |
| Group-level quota scope? | **Per-member inheritance** only | `maxFileSizeOverride` and `maxTotalStorageOverride` on Group are limits inherited by each member individually. No aggregate group quota. |
| Attributes beyond quotas? | **No** — quotas only for now | YAGNI. Permissions can be added later as column additions. |
| Delete group with members? | **Allow with confirmation** | Server does `SET NULL` (members fall back to global defaults). Frontend warns: "X members will be unassigned." |
| Admin UI placement? | **Separate page `/groups-management`** | Own entry in navbar admin dropdown, same level as User Management. |

## Data Model

### New: `Group`

```prisma
model Group {
  id          String   @id @default(cuid())
  name        String   @unique
  description String?

  // Per-member quota inheritance (null = inherit global, 0 = unlimited, >0 = bytes)
  maxFileSizeOverride     BigInt?
  maxTotalStorageOverride BigInt?

  // Future LDAP mapping (5.3) — DN of the AD group mapped to this group
  ldapDn String?

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  members User[]
}
```

### Modified: `User`

```prisma
model User {
  // ... existing fields ...
  groupId String?
  group   Group?  @relation(fields: [groupId], references: [id], onDelete: SetNull)
}
```

### Quota Resolution Order

```
user.maxFileSizeOverride        ?? →
  user.group?.maxFileSizeOverride ?? →
    (user.isAdmin ? 0n : global "maxFileSize")
```

Same for `maxTotalStorageOverride` / `maxTotalStoragePerUser`.

- `null` = inherit from next level
- `0` = unlimited
- `>0` = limit in bytes

## API — Module `group`

Location: `apps/server/src/modules/group/` (routes, controller, service, repository, dto)

All endpoints are admin-only (JWT + isAdmin preValidation).

### Endpoints

| Method | Route | Body / Params | Response | Description |
|--------|-------|---------------|----------|-------------|
| `GET` | `/groups` | — | `Group[]` with `memberCount`, `storageUsed` | List all groups |
| `GET` | `/groups/:id` | — | `Group` with `members[]` | Group detail with member list |
| `POST` | `/groups` | `{ name, description?, maxFileSizeOverride?, maxTotalStorageOverride? }` | `Group` | Create group |
| `PUT` | `/groups/:id` | `{ name?, description?, maxFileSizeOverride?, maxTotalStorageOverride? }` | `Group` | Update group |
| `DELETE` | `/groups/:id` | — | `{ message, unassignedCount }` | Delete group (SET NULL on members) |
| `POST` | `/groups/:id/members` | `{ userId }` | `{ message, previousGroupId? }` | Add user to group (moves if already in another group) |
| `DELETE` | `/groups/:id/members/:userId` | — | `{ message }` | Remove user from group |

### Response Schemas

**Group list item** (`GET /groups`):
```json
{
  "id": "clx...",
  "name": "Engineering",
  "description": "Engineering team",
  "memberCount": 12,
  "storageUsed": "5368709120",
  "maxFileSizeOverride": null,
  "maxTotalStorageOverride": "21474836480",
  "ldapDn": null,
  "createdAt": "...",
  "updatedAt": "..."
}
```

**Group detail** (`GET /groups/:id`): same fields + `members[]` array:
```json
{
  "members": [
    { "id": "...", "username": "jdoe", "email": "j@example.com", "storageUsed": "1073741824" }
  ]
}
```

### Validation (Zod)

- `name`: required, string, trimmed, min 1, max 100, unique (409 on conflict)
- `description`: optional string, max 500
- `maxFileSizeOverride`, `maxTotalStorageOverride`: reuse existing `quotaOverrideField` from `quota/dto.ts`
- `userId` (member endpoints): required, valid cuid

### Serialization

BigInt fields serialized as strings for JSON transport (same pattern as quota endpoints).

const maxFileSize =
  user.maxFileSizeOverride ??
  user.group?.maxFileSizeOverride ??
  (user.isAdmin ? 0n : BigInt(await getConfigValue("maxFileSize")));

const maxTotalStorage =

### Navigation

New entry in navbar admin dropdown (between Settings and User Management):
- Label: i18n key `nav.groups` → "Groups"

### Groups Table Columns

| Column | Content |
|--------|---------|
| Name | Group name |
| Description | Truncated to ~50 chars |
| Members | Badge with count |
| Max File Size | "Inherited" / "Unlimited" / formatted value |
| Max Storage | Same |
| Storage Used | Formatted total (informational, no progress bar) |
| Actions | Dropdown |

### Group Form Modal (Create/Edit)

Fields:
- Name (text input, required)
- Description (textarea, optional)
- Max File Size (Select: Inherit / Unlimited / Custom + FileSizeInput) — same pattern as user quota in user-form-modal
- Max Total Storage (same pattern)

### Group Detail Modal (View Members)

- List of members (username, email, individual storage used)
- "Add Member" button → combobox/search with autocomplete on username/email
- If selected user is already in another group, show inline warning: "This user is currently in group {name}. They will be moved to this group."
- Remove button per member row

### Delete Confirmation Modal

- Warning: "This group has X members. They will be unassigned from this group and their quotas will fall back to global defaults."
- Confirm / Cancel buttons

### Modification: User Form Modal (`/users-management`)

Add a "Group" Select field:
- Options: "None" + list of all groups (fetched from `GET /groups`)
- Displayed in the user edit form, below the role/status section
- Saving updates the user's `groupId`

### Modification: Quota Widget (User Edit)

When a user has a group with quotas, the quota display section shows the resolution source:
- "User override" / "Group: {groupName}" / "Global default" next to each effective value
- Helps the admin understand where the effective limit comes from
