## Summary

Track who downloads shared files and when, with per-invitee visibility.
Builds on 8.1 audit infrastructure for event logging and 8.2 invite mode
to identify individual recipients.

## Scope

### Core Tracking
- Log each download event: timestamp, file(s), invitee identity
- For non-invite shares (anonymous link): track download count + IP/user-agent only
- For invite-mode shares: track per-invitee download status (downloaded / not yet)

### Invite Mode (shared with 8.2)
- When creating a share, optionally add invitees (name + email)
- Each invitee gets a personal unique link
- Personal password auto-generated per invitee
- Invitation emails sent via 8.2 notification system

### Share Tracking View
- New modal/panel on share details: "Download Activity"
  - List of invitees with status (downloaded / pending)
  - Download timestamps per invitee
  - Ability to resend invitation email
  - Ability to send reminder to non-downloaders
- For anonymous shares: download count, last download timestamp

### Reverse Share Tracking
- Track upload events per reverse-share invitee
- Same invite-mode mechanics as regular shares

## Open Questions

1. How long to retain download logs? (tied to share lifetime? independent TTL?)
2. Should download tracking be visible to non-admin users who created the share?
3. Privacy considerations: should invitees be informed their downloads are tracked?
4. Database schema: separate `DownloadEvent` model or extend existing?
