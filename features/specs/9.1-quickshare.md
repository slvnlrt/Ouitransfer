# 9.1 — Quickshare

**Status:** Spec
**Depends on:** —

## Summary

A zero-friction file sharing block on the dashboard that lets authenticated users
share files in one gesture: drop files, optionally tweak settings, click "Partager".

## Design Decisions

- **Placement:** Primary block on the dashboard, above existing blocks (RecentFiles, RecentShares, QuickAccessCards)
- **UX model:** Inline state transitions (no modal) — dropzone → upload+options → confirmation
- **Complementary:** The existing "Create Share" flow (modal, select existing files) remains for advanced use cases
- **GlobalDropZone removal:** The current `GlobalDropZone` wrapping the entire dashboard is removed. Drop zones are scoped to explicit areas only (Quickshare block, UploadFileModal).

## Three States

### State 1 — Dropzone (initial)

A prominent drag-and-drop zone — the visual centerpiece of the dashboard.
- Dashed border, icon (CloudUpload or similar), text: "Déposez vos fichiers ici pour partager rapidement"
- Click to open file picker as alternative to drag-and-drop
- Follows existing UI design language (card style, indigo accent)

### State 2 — Upload + Options (after drop)

The block transforms into two sections:

**Top section — File list:**
- Each file: name, size, circular progress indicator, remove button
- Ability to drop/add more files while uploading
- Upload starts immediately on drop (reuses `useFileUpload` / `useUppyUpload`)

**Bottom section — Options (all optional, pre-filled with defaults):**
- **Name** — pre-filled: filename if single file, "X fichiers" if multiple. Editable.
- **Expiration** — dropdown: 1 day, 7 days (default), 30 days, never
- **Password** — toggle switch, password field appears when enabled. Off by default.
- **Recipients** — email input, simplified version of `RecipientSelector`. Collapsible. Empty by default.

**"Partager" button** — always visible and clickable:
- If upload is complete: creates share immediately
- If upload still in progress: button label changes to "Partage en cours..." with spinner, share is created automatically when all uploads finish

### State 3 — Confirmation (after successful share)

The block transforms into a success screen:
- Animated check icon
- Share link displayed prominently with "Copier le lien" button
- QR code of the link
- Summary line: "3 fichiers · expire dans 7 jours · pas de mot de passe"
- "Nouveau partage" button to reset to State 1

## Defaults (zero-config sharing)

| Setting | Default | Rationale |
|---------|---------|-----------|
| Name | Filename or "X fichiers" | Descriptive without effort |
| Alias | Auto-generated random slug | Every quickshare gets a shareable link |
| Expiration | 7 days | Safe default, avoids forgotten shares |
| Password | None | Minimal friction |
| Recipients | None | Optional, not pushed |

## Technical Flow

1. User drops file(s) on Quickshare block (dedicated dropzone, `GlobalDropZone` is removed)
2. Files added to Uppy, upload starts immediately via `useFileUpload` (presigned URL → S3 PUT → `registerFile`)
4. User can optionally adjust name, expiration, password, recipients
5. User clicks "Partager":
   - If all uploads complete: call `createShare` with file IDs + options, then `createShareAlias` for the link
   - If uploads pending: register intent, wait for all uploads to finish, then auto-create share
6. Share created → alias generated → transition to State 3
7. If recipients provided: auto-trigger `notifyRecipients` after share creation

### New

### Modified

- `dashboard/components/` — reorder existing blocks below QuickShare

### Removed
- `GlobalDropZone` component (`components/general/global-drop-zone.tsx`) — no longer used after Quickshare replaces its function on the dashboard

### Reused (no changes needed)
- `useFileUpload` / `useUppyUpload` — existing upload pipeline
- `createShare`, `createShareAlias` — existing share API
- `notifyRecipients` — existing notification API
- `RecipientSelector` — existing component (simplified usage)
