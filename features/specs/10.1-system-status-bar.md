# 10.1 — System Status Bar

**Status:** Spec
**Depends on:** —

## Summary

Replace the current `SystemStatus` card on the dashboard with a collapsible,
sticky status bar positioned just below the navbar. The bar is visible on all
pages, always starts collapsed as a small glassmorphism tab, and expands on click
to show system health, quotas, and metrics in a compact horizontal layout.

## Design Decisions

- **Placement:** Inside both `FileManagerLayout` and `PageLayout`, between
  `<Navbar />` and the content area. Both layouts share the same structure
  (Navbar + content + Footer). Sticky at `top-16` (below the 64px navbar),
  `z-30`.
- **Scope:** Visible on all authenticated pages, not just the dashboard.
- **Default state:** Always collapsed. No localStorage persistence.
- **No auto-expand:** Degraded/unhealthy status or quota warnings are communicated
  via the colored dot and pulse animation on the collapsed tab. The user manually
  expands to see details.
- **Glassmorphism:** Horizontal opacity gradient (alpha ~0.3 at edges, ~0.7-0.8
  at center) + `backdrop-blur` + subtle border (`border-white/5`) + inset
  highlight shadow. Works in both light and dark modes.
- **Mobile:** Expanded content stacks vertically instead of horizontal layout.
- **Data source:** Uses `useSystemStatus({ isExpanded })` with conditional
  polling (60s when expanded, 5 min when collapsed; admin stats only when
  expanded). `fileCount` and `activeShareCount` are available only on the
  dashboard page (via `DashboardMetricsContext`).

## Collapsed State

A small tab centered horizontally, hanging from the bottom of the navbar area:

- Shape: `rounded-b-lg`, no top border (attached to navbar edge)
- Background: glassmorphism gradient + backdrop-blur-xl
- Content:
  - Colored dot (8px, with colored glow/box-shadow):
    - Green (`#22c55e`) — healthy
    - Amber (`#f59e0b`) — degraded
    - Red (`#ef4444`) — unhealthy
  - Text: `dashboard.systemStatus.title` (i18n) — "System Status"
  - Chevron-down icon (12px)
  - Optional: quota percentage badge when `warningLevel` is `warning`, `critical`,
    or `exceeded` (e.g., amber badge showing "87%")
- Loading state: dot is gray (`#666`) with no pulse, text is dimmed. The tab is
  still interactive (clicking expands to show loading skeletons).
- Error state: dot is red, tab shows "System Status" in muted red. Expanding
  shows the existing `ErrorDisplay` inline variant with a retry button.
- Animations:
  - Dot pulses when degraded (2s cycle) or unhealthy (1.5s cycle)
  - Border tint matches status color when not healthy
  - Text color shifts to status color when degraded/unhealthy
  - Optional: stronger shake/pulse on state transition to degraded (optional
    follow-up, not implemented in v1)

## Expanded State

Full-width bar (same glassmorphism treatment) with content constrained to
`max-w-7xl` and centered.

### Title Row

- Same colored dot + "System Status" text + status label badge
  (Healthy/Degraded/Unhealthy)
- Right side: refresh button (RefreshCw icon) + chevron-up to collapse

### User View Content (~80px total height)

Horizontal layout with two sections:

1. **Storage Quota** (flex-1, min-width 200px):
   - Label + percentage
   - Compact progress bar (h-1.5)
   - Used/total text (10px)
   - Color-coded by warning level (indigo/yellow/orange/red)

2. **Personal Metrics** (flex, gap):
   - "My files" count (large number + small label below)
   - "Active shares" count (same style)
   - Only shown when `fileCount`/`activeShareCount` are provided (dashboard only)

Quota warning/exceeded banners from the current implementation are **not** shown
in the bar (too tall). The progress bar color and the collapsed tab badge are
sufficient indicators.

### Admin View Content (~90px total height)

Horizontal layout with three sections separated by vertical dividers:

1. **Health Checks** (flex, gap):
   - Database: check icon (green/red) + "DB" label
   - Storage: check icon (green/amber/red) + "Storage" label
   - Uptime: "Up:" + formatted duration

2. **Disk Space** (flex-1, min-width 160px):
   - Label + percentage
   - Compact progress bar (h-1.5)
   - Used/total text

3. **Platform Metrics** (flex, gap):
   - Users (active/total)
   - Files (total)
   - Shares (active count)

~~Admin personal quota display (when admin has a quota override) is shown as an
additional progress bar below disk space, only when applicable.~~ Removed: the
admin view shows only the platform disk space bar. `DiskSpaceInfo` doesn't
distinguish admin personal quota from platform disk usage, so the duplicate bar
was always identical.

### Mobile Layout (< 640px)

All sections stack vertically with horizontal separators instead of vertical
dividers. Each section takes full width.

## Animation & Transitions

- **Expand/collapse:** `transition-[grid-template-rows] duration-300 ease-in-out`.
  Uses CSS `grid-template-rows: 0fr` / `1fr` trick for smooth height animation
  without JavaScript measurement. Expanded panel is always in DOM, wrapped in
  `overflow-hidden min-h-0` with `aria-hidden` when collapsed.
- **Dot pulse:** CSS `@keyframes pulse` with opacity oscillation.
- **Refresh spin:** `animate-spin` on RefreshCw icon while `isRefreshing`.

## i18n

Existing keys under `dashboard.systemStatus.*` are reused. New keys needed:

| Key | en-US | Purpose |
|-----|-------|---------|
| `dashboard.systemStatus.collapse` | `"Collapse system status"` | Aria label for collapse button |
| `dashboard.systemStatus.expand` | `"Expand system status"` | Aria label for expand button/tab |

These must be added to all 23 locale files.

## Accessibility

- Collapsed tab: `<button>` with `aria-expanded="false"` and
  `aria-label={t("expand")}`.
- Expanded bar: panel with `aria-label={t("title")}`. Note: `<section aria-label>`
  is used instead of `<div role="region">`, which is semantically equivalent per
  WAI-ARIA. Collapse button has `aria-label={t("collapse")}`.
- Refresh button: existing `aria-label={t("refresh")}`.
- Progress bars: existing `aria-label` attributes preserved.

## Dashboard Metrics Context

`fileCount` and `activeShareCount` are currently passed as props from
`useDashboard()`. Since the bar is now global but these values are only available
on the dashboard, we use a lightweight React context:

- `DashboardMetricsProvider` wraps the dashboard page content
- Provides `{ fileCount?: number; activeShareCount?: number }`
- `SystemStatusBar` reads from this context; if no provider is present (non-
  dashboard pages), the personal metrics section is simply not rendered

This avoids fetching dashboard-specific data on every page.

## Out of Scope

- Server-side changes (no API modifications)
- Changes to `useSystemStatus()` logic or data fetching
- Full quota warning banners (removed from bar, the card format was better suited;
  if needed later, could be a separate toast/notification system)
