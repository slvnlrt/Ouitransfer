# 6.1 — UI Code Audit

## Goal

Audit the entire `apps/web/` frontend codebase for UI code quality:
- Consistency of patterns (how components are structured, styled, composed)
- Opportunities to extract reusable components
- shadcn/ui usage (correct use of primitives, unnecessary custom implementations)
- Tailwind CSS usage (inconsistent class patterns, magic values, missing design tokens)
- Component file organization (too large, mixed concerns, unclear naming)
- Accessibility gaps (semantic HTML, ARIA attributes, focus management)
- Dead or redundant UI code

## Scope

- All files under `apps/web/src/components/`
- All page/layout files under `apps/web/src/app/`
- Shared hooks related to UI (`useEditableItem`, `useSelectionManager`, etc.)
- Tailwind config and any custom CSS

## Out of Scope

- Backend code
- API/data layer (already hardened in Phase 5)
- i18n content (translation values themselves)

## Deliverable

A structured audit report in `features/reviews/6.1-ui-audit-report.md` with:
- Findings grouped by category (consistency, extraction, accessibility, dead code, etc.)
- Severity: Critical / Important / Minor
- Specific file:line references
- Recommended actions (grouped into logical batches for 6.2)

## Open Questions

- None — this is an investigative phase
