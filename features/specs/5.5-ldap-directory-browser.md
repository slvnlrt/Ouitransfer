# 5.5 — LDAP Directory Browser (pick DNs from the tree)

**Status:** Spec

## Goal

Remove the friction of hand-typing Distinguished Names in the LDAP config. Today an admin
must type three error-prone DNs (`searchBase`, `syncGroupDn`, and `bindDn`). This feature lets
the admin **bind once and pick DNs directly from the live directory**:

- **Base DN (`searchBase`)** — one-click auto-detect from RootDSE **+** a lazy directory tree to
  drill into OUs/containers and select the base.
- **Sync Group (`syncGroupDn`)** — a **search box** ("type to find a group") that queries the
  directory and lists matching groups.

The `bindDn` stays free-text: AD accepts UPN (`user@domain`) and down-level (`DOMAIN\user`) bind
names, which are easier to type than a DN and not always browsable.

## Decisions (resolved with owner)

1. **Scope of pickable fields:** Base DN + Sync Group. Bind DN remains free-text.
2. **Group selection UX:** search box (not tree navigation) — practical for deep/large directories.
3. **No re-typing the bind password:** the browser reuses the stored encrypted bind password when
   the form holds the masked value (`••••••••`), mirroring the `PUT /config` masked-password rule.
   If the admin typed a fresh password, that one is used (lets you browse before first save).
4. **No audit logging of browse/search** (I-2): browse and group-search are read-only, config-time
   directory reads against an admin-supplied bind — the same class as `POST /admin/ldap/test`, which is
   **not** audit-logged (no `LDAP_TEST` action exists in `audit/service.ts`). We follow that precedent and
   do **not** log them. Only state-changing LDAP actions stay logged (`LDAP_CONFIG_UPDATE`, `LDAP_SYNC_TRIGGERED`).
5. **No per-route rate limit** (M-1): consistent with `POST /admin/ldap/test`, which has none. Both routes
   are admin-gated (post-auth) and CSRF-protected (the global `@fastify/csrf-protection` double-submit guard
   applies to every `POST`), so unbounded binds are at worst an authenticated-admin self-DoS.

## Security model (consistent with the existing LDAP hardening)

The browse/search endpoints intentionally expose directory topology **to the authenticated admin**
who is configuring LDAP — the same admin who already supplies the bind credentials. This is the
configuration surface, not a public oracle. Concretely:

- **Admin-gated**, `createAdminPreValidation({ allowSetupBypass: false })` — same as all other LDAP routes.
- **SSRF/egress guard**: every connection goes through `LdapClient.connect()` → `assertLdapTargetAllowed`
  (scheme check, cloud-metadata block, optional `LDAP_ALLOWED_HOSTS` lockdown). No new egress path.
- **No topology in error messages**: on failure, surface only our own `LDAP_*` config errors
  (scheme/SSRF/attribute), otherwise log server-side and return a generic message — identical to
  `testConnection`. Success returns topology (that's the point); failures never become a port-scan oracle.
- **Filter-injection (C-1 — mandatory)**: the group-search query MUST be composed as an `ldapts`
  **filter object** (`SubstringFilter` — note the singular name — wrapped in `OrFilter`/`AndFilter`),
  exactly like the existing `searchSyncGroupMembers` (`ldap.client.ts:93-99`). ldapts only escapes the
  value when it BER-encodes a filter **object**; a filter passed as a **string** is parsed by
  `FilterParser.parseString`, where `* ( ) \` are syntax, **not** escaped data — so a query like
  `)(uid=*` would inject filter logic. The query is therefore **never** interpolated into a filter
  string. A unit test asserts a query containing `*()\` is carried as a substring value (object), not
  parsed as syntax. `baseDn`/`searchBase` are search bases, not filter values — not injectable — and are
  still validated to DN shape by Zod.
- **Bounded responses**: every search sets a `sizeLimit` cap (containers ~200, groups ~50) and reports
  truncation, so a hostile/huge directory cannot dump unbounded data or DoS the request.

## Server design (`apps/server/src/modules/ldap/`)

### Shared bind-password resolution (I-3)
A small helper resolves the effective bind password for an incoming request body:
if `bindPassword` is empty or equals `MASKED_PASSWORD`, load the stored config and `decrypt()` it;
otherwise use the supplied value. Used by both new routes. Contract:
- **Hoist `MASKED_PASSWORD`** out of `routes.ts:16` (currently a module-local const) into a shared
  location (e.g. `ldap/constants.ts`) imported by `routes.ts` and the helper — no duplicated magic string.
- **No stored config/password yet** (browsing before first save with a masked/empty field) → throw a
  clear `LDAP_*` validation error telling the admin to enter the bind password.
- **`decrypt()` failure** when reusing the stored password (missing/invalid `ENCRYPTION_SECRET` — the
  status endpoint already warns about this, `routes.ts:300-301`) → surface a clear `LDAP_*` config error
  so it reaches the admin, **not** genericized as "connection failed". This maps through the
  "only `LDAP_*` codes are surfaced" rule below.

### New `LdapClient` methods
- `readRootDse()` → `{ namingContexts: string[]; defaultNamingContext: string | null }`
  RootDSE read: base `""`, scope `base`, filter `(objectClass=*)`, attributes
  `["namingContexts","defaultNamingContext"]`. **Non-AD degradation (I-1):** `defaultNamingContext` is
  Microsoft-AD-specific (absent on OpenLDAP / 389-DS / FreeIPA) → it is `null` there, and the helper must
  not assume it exists. Empty-string naming contexts (the rootDSE `""` entry some servers expose) are
  **filtered out** of `namingContexts` before being offered as browsable bases (they fail the `ldapDn`
  regex and are not a valid base to pick).
- `browseContainers(baseDn)` → `LdapDirectoryNode[]`
  `scope: "one"` under `baseDn`, filter `(|(objectClass=organizationalUnit)(objectClass=container)(objectClass=domainDNS)(objectClass=builtinDomain))`,
  attributes `["ou","cn","name","objectClass"]`, `sizeLimit` ≈ 200. Maps to nodes, sorted by name.
  (AD well-known containers `CN=Users`/`CN=Builtin`/`CN=Computers` are `container`/`builtinDomain` and are
  covered; user OUs are `organizationalUnit`. The objectClass set is unit-tested against AD-shaped fixtures.)
- `searchGroups(searchBase, query)` → `LdapDirectoryNode[]`
  `scope: "sub"` from `searchBase`, filter composed as **objects** (C-1):
  `AndFilter([ EqualityFilter(objectClass=group), OrFilter([ SubstringFilter(cn, any:[query]), SubstringFilter(sAMAccountName, any:[query]) ]) ])`,
  attributes `["cn","name"]`, `sizeLimit` ≈ 50; report `truncated` when the cap is hit.

`LdapDirectoryNode = { dn: string; name: string; type: "ou" | "container" | "domain" | "group"; hasChildren: boolean }`.
`type` drives the tree icon; `hasChildren` is `true` for container-type nodes (`ou`/`container`/`domain`),
`false` for leaves — it controls whether an expand affordance is shown **without** a child-count probe.
**Expand tri-state (I-4):** a container shows an expand arrow; on first expand it loads children once and
caches the loaded/empty result. If the load returns `[]`, the node is marked **loaded-empty** — the arrow
collapses and a muted "no sub-containers" row is shown; re-expanding does **not** refetch. The three states
(not-loaded / loading / loaded[-empty]) are explicit so the reviewer can verify them.

### New routes (both `POST`, admin-gated)
- `POST /admin/ldap/browse` — body: connection fields + optional `baseDn` (DN-validated).
  - No `baseDn` → `{ nodes: LdapDirectoryNode[]; defaultBaseDn: string | null }` (naming contexts as
    `type: "domain"` roots; `defaultBaseDn` = `defaultNamingContext` for the one-click "use this" action).
  - With `baseDn` → `{ nodes: LdapDirectoryNode[]; defaultBaseDn: null }` (children of that node).
- `POST /admin/ldap/search-groups` — body: connection fields + `searchBase` (DN-validated) + `query`
  (1–256 chars) → `{ groups: LdapDirectoryNode[]; truncated: boolean }`.

Both wrap in try/catch → generic error on non-`LDAP_*` failures, `disconnect()` in `finally`.

### DTO
New `LdapConnectionFieldsSchema` (serverUrl, bindDn, `bindPassword: z.string()` — empty/masked allowed,
useTls, tlsSkipVerify) reused by both bodies + `LdapBrowseSchema` / `LdapSearchGroupsSchema`.

## Web design (`apps/web/src/app/admin/ldap/`)

### HTTP layer (`src/http/endpoints/ldap/`)
Add `browseDirectory(body)` and `searchGroups(body)` calls + their response types.

### Components
- `ldap-directory-browser.tsx` — Dialog with a **lazy tree**. On open: `browse` with no `baseDn` →
  render naming contexts + a prominent "Use detected base (`defaultBaseDn`)" action **when present**;
  when `defaultBaseDn` is `null` (non-AD, I-1) that shortcut is hidden and the admin picks from the
  naming-context roots. Expanding a node → `browse` with that `baseDn`. Selecting a node →
  `setValue("searchBase", dn)` and close.
- `ldap-group-search.tsx` — Dialog with a **debounced search input** → `search-groups` →
  list of `{ name, dn }` → selecting sets `syncGroupDn`. **Race-safety (M-4):** queries run through
  TanStack Query keyed by the query string (or an `AbortController`) so only the latest query's results
  render — a slow `"ad"` response never overwrites a newer `"admin"` one. The `truncated` flag surfaces a
  "refine your search" hint.

### Accessibility (M-3)
- Tree uses `role="tree"` / `role="treeitem"` with `aria-expanded` on container nodes and roving-tabindex
  keyboard nav (←/→ collapse/expand, ↑/↓ move, Enter/Space select).
- Dialogs use the shadcn `Dialog` focus-trap; initial focus targets the search input (group) or the
  detected-base action / first root (browser), and focus returns to the triggering "Browse" button on close.
- The group-search result count is announced via an `aria-live="polite"` region (mirrors the existing
  test-result live region, `ldap-config-form.tsx:216-219`).

### Config form integration (`ldap-config-form.tsx`)
- "Browse" button (folder-tree icon) next to the Base DN input → opens the directory browser.
- "Browse" button (search icon) next to the Sync Group input → opens the group search.
- Buttons enabled when `serverUrl` + `bindDn` are present **and** a usable password exists
  (typed in the form OR the config is already saved, i.e. masked password resolvable server-side).
- **The group-search button additionally requires a non-empty, valid `searchBase`** (M-6) — the group
  search roots its `scope:"sub"` at that base; with no base it would error. Pick the Base DN first.
- The dialogs receive the current form connection values (serverUrl, bindDn, bindPassword, useTls,
  tlsSkipVerify) so browsing reflects unsaved edits.

### Type parity (plan dependency)
The web HTTP layer (`http/endpoints/ldap/types.ts`) mirrors `LdapDirectoryNode` and the new response
shapes by hand — the project duplicates server/web types rather than sharing them (cf. existing
`LdapTestBody`/`LdapTestResult`). Lot 1 must finalize these shapes before Lot 2 consumes them.

### i18n (M-5)
New `ldap.browse.*` namespace added to all 23 locale files (structure parity enforced by
`apps/web/src/__tests__/locale-keys.test.ts`, which checks structure, not translation quality).
`en-US` + `fr-FR` fully translated; 21 other locales get English placeholders, consistent with the
accepted TD-36 pattern (also used by TD-42). The 21 placeholders are **recorded under TD-36 in
`features/TECHNICAL-DEBT.md`**, not silently shipped.

## Tests
- **Server unit**: `LdapClient.readRootDse/browseContainers/searchGroups` against a mocked `ldapts` client
  (filter shape, sizeLimit, node mapping/sorting; empty-NC filtering and null `defaultNamingContext` for
  non-AD). **C-1 injection test**: a group query containing `*()\` is carried as a `SubstringFilter` value
  (object), never interpolated into a filter string.
- **Server integration (`app.inject()`)**: both routes — admin gate, masked-password resolution (stored vs
  typed; **no-stored-config** and **`ENCRYPTION_SECRET`-unset** both yield a surfaced `LDAP_*` error, not a
  generic one), DN/query validation, generic error on bind failure (no topology leak), truncation flag.
- **Web**: directory-browser tree (lazy expand, loaded-empty tri-state, auto-detect action present/absent,
  select), group-search (debounce race-safety, `searchBase`-gated button, select), and basic a11y
  (tree roles, dialog focus) with mocked endpoints.

## Out of scope
- Bind DN picker (UPN/down-level free-text is sufficient).
- Topology caching / persistent tree state.
- Multi-select or browsing arbitrary attribute values.
