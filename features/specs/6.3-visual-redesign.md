# 6.3 — Visual Redesign

## Goal

Give Ouitransfer a new visual identity after the project takeover. The redesign signals a fresh start and a professional product.

## Design Direction

- **Smart, sober, corporate** — professional look that inspires trust
- **Wow factor** — subtle animations, refined transitions, attention to micro-interactions
- **Not boring** — the design should feel premium and polished, not generic enterprise
- **Dark mode first** — dark mode is the premium feel; light mode is the clean professional variant

## Decisions

### 1. Primary Color — Deep Indigo/Blue

Replace the current green (`oklch(0.5927 0.1767 142.49)`, hue 142) with a **deep indigo-blue** (hue ~260-270).

**Rationale:** Indigo conveys trust, professionalism, and technology. It's serious without being cold (unlike pure blue) and distinctive without being flashy. It pairs naturally with white/gray neutrals for a corporate feel while supporting vibrant accents.

**Light mode values:**
- `--primary: oklch(0.45 0.2 265)` — deep indigo (darker, more authoritative)
- `--primary-foreground: oklch(0.985 0 0)` — white text on primary
- `--ring: oklch(0.55 0.18 265)` — slightly lighter for focus rings

**Dark mode values:**
- `--primary: oklch(0.65 0.18 265)` — lighter indigo (readable on dark backgrounds)
- `--primary-foreground: oklch(0.15 0 0)` — dark text on primary buttons
- `--ring: oklch(0.55 0.18 265)`

**Accent color (secondary highlight):** A warm amber/gold for CTAs and success states:
- Light: `oklch(0.75 0.15 75)` — warm gold
- Dark: `oklch(0.80 0.14 75)` — slightly brighter

### 2. Logo — Keep, Re-color

Keep the existing logo shape. The customization system already allows runtime color changes. The logo will inherit the new primary color naturally.

### 3. Gradients — Yes, Subtle

Use subtle gradients for:
- **Hero sections / landing page** — soft gradient backgrounds (indigo → deep blue → near-black in dark mode)
- **Card headers** — optional subtle top-border gradient for premium cards
- **CTA buttons** — subtle gradient for primary actions (not flat)
- **Sidebar/nav highlights** — gradient accent for active items

Keep flat design for:
- Regular content cards
- Form inputs
- Tables and data-heavy pages

### 4. Animation Library — Keep `motion`

Continue using `motion` (framer-motion). It's already integrated, supports sophisticated animations, and the bundle impact is acceptable for this app. CSS transitions for simple hover/focus states; `motion` for page transitions, entrance animations, and the background effect.

### 5. Theme Approach — Custom Theme from Scratch

Build a fully custom theme on top of shadcn/ui primitives. The current theme is essentially "green shadcn default" — we replace it with a bespoke palette.

### 6. Typography — Inter as Default

Switch from Outfit (geometric, playful) to **Inter** (humanist, professional).
- Inter is already loaded in the font picker (available as alternative font)
- Better readability at small sizes, more professional at all sizes
- Variable font: use weight 400 (body), 500 (labels), 600 (headings), 700 (hero)
- The customization system still allows users to switch fonts

### 7. Border Radius — Slightly Reduced

Change default from `0.5rem` to `0.625rem`. Slightly more rounded than typical corporate but not bubbly. This gives a modern, approachable feel.

### 8. Backgrounds

**Dark mode:**
- Near-black base: `oklch(0.13 0.01 265)` — very subtle blue undertone (not pure gray)
- Cards: `oklch(0.18 0.01 265)` — slight elevation via color, not shadow
- Subtle noise texture overlay (CSS only, no image) for depth

**Light mode:**
- Off-white base: `oklch(0.985 0.005 265)` — tiny blue cast (not warm gray)
- Cards: pure white `oklch(1 0 0)`
- Subtle border hierarchy: cards have `border-border/80`, sections use `border-border/40`

### 9. Background Effect (BackgroundLights Replacement)

Replace the current breathing green glow blobs with:
- **Dark mode:** Subtle gradient mesh (static or very slow drift) with indigo/deep-blue tones. More sophisticated than a simple radial glow.
- **Light mode:** Very subtle, nearly invisible tint — a soft gradient wash at top-left only.
- No more infinite scale animations (felt cheap). If animated, use very slow color shifts (20s+ cycle).

### 10. Component Refinements

**Buttons:**
- Primary: gradient fill (indigo-dark to indigo-light), subtle shadow, scale(1.02) on hover
- Secondary: ghost with border, subtle background on hover
- Destructive: keep red/orange, muted in non-hover state

**Cards:**
- Tighter padding (p-5 instead of p-6 default where appropriate)
- Subtle shadow in light mode (`shadow-sm`), no shadow in dark mode (rely on background color difference)
- Hover: slight translateY(-1px) + shadow increase for interactive cards

**Inputs:**
- Sharper border (`border-border/80`), no backdrop-blur (was overused)
- Focus: indigo ring glow (`ring-primary/30`)

**Modals:**
- Slide-in-from-bottom + fade (replace instant appear)
- Subtle backdrop blur

**Navigation:**
- Active item: left border accent (3px solid primary) + subtle background tint
- Hover: background tint only
- Remove backdrop-blur from navbar (cleaner, better performance)

**Tables:**
- Alternating row tints in light mode (very subtle `bg-muted/30`)
- Hover row highlight
- Header row: `bg-muted/50` with `font-medium` (not bold)

### 11. Micro-Animations

- **Page transitions:** fade-in (200ms) + subtle translateY(8px → 0)
- **Card hover:** translateY(-1px), shadow grow (150ms ease)
- **Button hover:** scale(1.02), 100ms
- **Toast entry:** slide-in from right
- **Loading states:** skeleton pulse at 1.5s (slower, more premium feel)
- **Icon interactions:** rotate/bounce on specific actions (delete → shake, success → check-pop)

### 12. Dark Mode Refinements

- Background has a slight blue undertone (not pure neutral)
- Borders use `oklch(1 0 0 / 12%)` (slightly less visible than current 15%)
- Card elevation via color, not shadow
- Primary color is lighter in dark mode (accessibility — contrast ratio ≥ 4.5:1)
- Text hierarchy: `oklch(0.98 0 0)` for headings, `oklch(0.7 0.01 265)` for muted (slight blue tint)

### 13. Customization System Preservation

The existing runtime customization (primary color, font, radius, background) via localStorage/ThemeColorProvider **must continue to work**. The redesign changes the **defaults** only. User overrides take precedence.

Fix the `StaticBackgroundLights` component which currently hardcodes `rgba(34,197,94,...)` (green-500) — must use CSS variable reference like `BackgroundLights` does.

## Scope

- Global color palette (CSS variables in `globals.css`)
- Component visual refresh (buttons, cards, inputs, modals, dropdowns)
- Page layouts (dashboard, settings, share pages, admin)
- Landing page (hero, animations, palette)
- Login / registration flow
- Navigation (navbar)
- Loading states, empty states, error states
- Background effects (replace green glow)
- Micro-animations (hover, transitions, entrances)

## Out of Scope

- Structural HTML changes (handled in 6.2)
- New features (handled in 5.x track)
- Backend changes
- Sidebar (app doesn't have one currently — uses top navbar)
