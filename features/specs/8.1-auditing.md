# 8.1 — Audit Trail / Activity Log

**Status:** Not started
**Depends on:** — (foundational infrastructure)

## Summary

System-wide audit trail that logs all significant actions performed in the application.
Provides an admin-facing view for reviewing activity, and serves as the data layer
for downstream features (download tracking 8.3, email notifications 8.2).

## Scope

### Core Audit Infrastructure
- `AuditEvent` model: timestamp, actor (user ID or "system"), action type, target entity
  (share, reverse-share, user, group, file, settings…), target ID, metadata (JSON), IP address
- Write-only append log (no edits, no deletes — immutable)
- Service-layer `auditLog.record(...)` helper callable from any module

### Actions to Audit (non-exhaustive)
- **Auth:** login, logout, login failed, password change, 2FA enable/disable, account locked
- **Users:** create, update, delete, role change, quota change, group assignment
- **Groups:** create, update, delete, LDAP mapping change
- **Shares:** create, update, delete, download (who, when), password change, expiry change
- **Reverse Shares:** create, update, delete, upload received, file deleted
- **Files:** upload, download, delete, bulk delete
- **Settings:** any config change (key + old value + new value)
- **LDAP:** sync triggered, sync completed (with stats), sync error
- **Admin:** auth provider create/update/delete, storage config change

### Admin View
- Dedicated admin page (`/admin/audit` or `/admin/activity`)
- Filterable table: by actor, action type, target type, date range
- Searchable: free-text search on metadata
- Paginated (server-side), sortable by date
- Export to CSV/JSON (optional, nice-to-have)

### Retention & Performance
- Configurable retention period (e.g., 90 days, 1 year, forever)
- Index on timestamp + actor + action type for fast queries
- Background cleanup job for expired entries (ties into 5.2 auto-cleanup)

## Open Questions

1. SQLite performance with high-volume audit logs? May need periodic archival/rotation.
2. Should audit events be visible to non-admin users for their own actions? (e.g., "my activity" in profile)
3. Real-time streaming (WebSocket) for live audit dashboard? Or just polling/refresh?
4. Should sensitive data (passwords, tokens) be redacted or omitted from metadata?
