## Findings converted to TODO comments instead of real fixes

These were findings from reviewers that I (the orchestrating agent) downgraded to "add a comment" in the fix prompts, violating the project's quality standard.

### 1. `share_downloaded` loses visitor identity

- **Review**: Pass 5 Integration M-8
- **File**: `apps/server/src/modules/file/routes.ts` (near `trackShareDownload`)
- **Problem**: Download notifications don't include visitor name/email even when the visitor is identifiable via `sv_{alias}` cookie or `?t=` tracking token. The download endpoint doesn't parse these.
- **What was done**: Added a TODO comment instead of implementing the fix.
- **Real fix needed**: Parse `sv_{alias}` cookie and `?t=` tracking token in `POST /files/download-url` and `POST /files/download`, thread the result into `trackShareDownload`, include visitor identity in `share_downloaded` notification payload.

### 2. `getShare` by ID doesn't parse visitor cookie

- **Review**: Pass 5 Integration M-9
- **File**: `apps/server/src/modules/share/routes.ts` (near `GET /shares/:shareId`)
- **Problem**: Only alias-based routes parse the visitor identification cookie. The by-ID route doesn't, creating an inconsistency in the identification gate.
- **What was done**: Added a comment instead of implementing.
- **Real fix needed**: Either parse the cookie on the by-ID route too (requires resolving alias from shareId), or document as intentional design with a clear rationale in the spec.

### 3. Audit metadata stores plaintext emails (PII) — no deletion sweep

- **Review**: Pass 5 Integration M-5 (also flagged in pass 4)
- **File**: `apps/server/src/modules/share/routes.ts` (audit log calls)
- **Problem**: `AuditLog.metadata.emails` persists recipient emails in plaintext. `deleteUser` doesn't sweep these rows. GDPR data-subject deletion would leave PII behind.
- **What was done**: Added a TODO comment.
- **Real fix needed**: `deleteUser` must sweep `AuditLog` rows containing the deleted user's email in `metadata`. Or redact the email from metadata at deletion time.

### 4. `admin_user_registered` includes the acting admin

- **Review**: Pass 5 Integration M-3
- **File**: `apps/server/src/modules/user/service.ts`
- **Problem**: When an admin creates a user, `sendToAdmins` notifies ALL admins including the one who just performed the action.
- **What was done**: Added a comment saying "some teams want this."
- **Real fix needed**: Plumb `actingAdminId` into `register()` and exclude them from the fan-out. Or make a product decision and document it in the spec.

### 5. Sender locale used for external recipient invitations

- **Review**: Pass 5 Core M-3
- **File**: `apps/server/src/modules/share/service.ts`

- **Real fix needed**: Consider adding an optional `locale` field to `ShareRecipient`. Low priority but should be a tracked decision, not a spec footnote.
