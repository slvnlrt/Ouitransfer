# Review — 9.1 Quickshare

**Date:** 2026-05-22
**Reviewer:** Final code review agent (spec + quality)
**Scope:** All 7 implementation commits (`7377af7` through `973e36a`)

All findings addressed in commits `4005462` (Critical + Important) and `25b8dd6` (Minor).

---

## Critical

- [x] **C1** — `use-quick-share.ts` : Multi-batch upload bug. Le second drop de fichiers ne déclenchait jamais l'upload (`startUpload()` appelé uniquement sur la transition `dropzone → uploading` via `setTimeout` sans cleanup). Les fichiers ajoutés en état `uploading` restaient `pending` indéfiniment. Corrigé par un `useEffect` réactif sur `fileUploads` + `state`, avec cleanup du timer.

## Important

- [x] **I1** — `quick-share-dropzone.tsx` : Card non accessible au clavier (pas de `role="button"`, `tabIndex`, ni `onKeyDown`). Ajout de `role="button"`, `tabIndex={0}`, `aria-label={t("title")}` et handler `onKeyDown` (Enter/Space).

- [x] **I2** — `quick-share-confirmation.tsx` : Bouton copier icon-only sans `aria-label`. Ajout de `aria-label={t("copyLink")}` (clé déjà définie en i18n).

- [x] **I3** — `use-quick-share.ts` : Early return dans `performShare` (quand `fileIds.length === 0`) ne réinitialisait pas `pendingShare`. Ajout de `setPendingShare(false)` défensif avant le `return`.

- [x] **I4** — `quick-share-upload.tsx` : Boutons remove et retry non désactivés pendant `isSubmitting`. Suppression d'un fichier en cours de soumission causait une confusion d'état. Ajout de `disabled={isSubmitting}` sur les deux boutons.

- [x] **I5** — `use-quick-share.ts` : Si `createShareAlias` échoue, le share était déjà créé côté serveur (share orphelin). Remplacé par une boucle de retry (3 tentatives avec alias différent). En cas d'échec total, suppression best-effort du share via `deleteShare`.

- [x] **I6** — `use-quick-share.ts` : `setTimeout` dans `handleFilesAdded` sans `clearTimeout`. Résolu par le fix C1 (suppression du `setTimeout`, remplacé par le `useEffect`).

## Minor

- [x] **M1** — 23 fichiers locales : Clé `quickShare.upload.recipients.toggle` morte (jamais utilisée dans le code). Supprimée de tous les fichiers. La clé `copyLink` était également inutilisée, maintenant utilisée par le fix I2.

- [x] **M2** — `use-uppy-upload.ts` : Type `onAfterUpload` retournait `Promise<string | undefined>` alors que `string | void` est plus permissif et évite de forcer `return undefined;` explicite chez les appelants. Type corrigé en `Promise<string | void>`, `return undefined;` retiré de `file-upload-section.tsx`.

- [x] **M3** — `quick-share-dropzone.tsx` : Guards `application/x-move-item` dans `handleDragEnter` et `handleDrop`. Ce type DnD est propre au file manager, pas au dashboard. Guards supprimés.

- [x] **M4** — `quick-share-dropzone.tsx`, `quick-share-upload.tsx` : `<input type="file" className="hidden">` sans `aria-hidden`. Ajout de `aria-hidden="true"` sur les deux inputs cachés.

- [x] **M5** — `use-quick-share.test.ts` : Assertions faibles (le mock `useTranslations` retourne la clé, donc `toContain("3")` passe trivialement). Accepté en l'état — smoke tests explicites. Nouveau test ajouté pour le cas multi-batch (C1).

- [x] **M6** — `quick-share-upload.tsx` : L'overlay de drag sur la card upload utilisait la même clé i18n `addMore` que le bouton header. Ajout d'une clé dédiée `dropToAdd` dans les 23 locales, utilisée dans l'overlay.

- [x] **M7** — `quick-share-upload.tsx`, `quick-share.tsx` : Prop `isUploading` passée à `QuickShareUpload` mais jamais utilisée dans le composant (`_isUploading`). Prop retirée de l'interface, du destructuring et du JSX parent.

- [x] **M8** — `use-quick-share.ts` : `shareAlias` exposé dans le return du hook mais jamais consommé par les composants. Retiré de l'objet retourné (variable interne conservée pour la logique de retry I5).

- [x] **M9** — `use-quick-share.ts` : Contrat fragile autour de `nameTouchedRef` (updateSettings marque toujours touched même si la valeur est inchangée). Non corrigé — pas de bug reproductible dans l'usage actuel.

- [x] **M10** — `quick-share-confirmation.tsx` : Taille QR SVG (180px visible) vs canvas de téléchargement (256px). Cohérent avec le pattern existant dans `share-multiple-items-modal.tsx`. Non modifié.
