# Review — 5.3 LDAP/AD Sync (Server)

## Critical

- [ ] **C-1.** TLS certificate verification disabled — MITM risk on LDAPS. `ldap.client.ts:32` sets `rejectUnauthorized: false`. In a DMZ deployment, attacker can intercept LDAPS traffic and steal bind credentials. Fix: default to strict validation, add `tlsSkipVerify` boolean field to `LdapConfig` schema (default false), pass `rejectUnauthorized: !config.tlsSkipVerify` to `tlsOptions`. Show UI warning when verification is disabled.
- [ ] **C-2.** LDAP injection in search filter — no DN escaping. `ldap.client.ts:44` interpolates `config.syncGroupDn` raw into LDAP filter string. Spec promised escaping (§Security). Fix: use ldapts filter classes (`EqualityFilter`, `AndFilter`) or escape per RFC 4515 (`*`, `(`, `)`, `\`, NUL).
- [ ] **C-3.** Wrong email sent to LDAP users — `sync.service.ts:357` calls `sendPasswordResetEmail` instead of `sendLdapWelcomeEmail`. The welcome email method exists but is never called (dead code). Also: email body says "1 hour" but code sets 7-day expiry. Fix: wire `sendLdapWelcomeEmail`, update expiry text to match 7-day TTL.
- [ ] **C-4.** LDAP users can't set password when `passwordAuthEnabled=false`. `auth/service.ts:178-184` gates `resetPassword` on this setting. Spec explicitly says password reset must work for LDAP users regardless of toggle. Fix: allow password reset when user has non-null `ldapDn` regardless of `passwordAuthEnabled`. Add integration test.
- [ ] **C-5.** Non-atomic user create + passwordReset — orphan risk. `sync.service.ts:307-335` creates user and passwordReset token in separate calls. If token creation fails, user exists but can't receive welcome email, and next sync won't re-send. Fix: wrap `user.create` + `passwordReset.create` in `prisma.$transaction()`. Surface email failures in sync log details (not just debug log).
- [ ] **C-6.** `setInterval` overlap risk — scheduler fires on wall-clock cadence. `sync.scheduler.ts:20-27` — if sync takes longer than interval, next tick hits mutex and wastes slot. `schedulerNextSyncAt` goes out of sync. Fix: use chained `setTimeout` pattern (schedule next after current run completes).
- [ ] **C-7.** `initSchedulerOnBoot` can hang server startup. `server.ts:96` — `await initSchedulerOnBoot()` blocks boot on slow DB. Fix: fire-and-forget with `void initSchedulerOnBoot()` (function already has internal try/catch).

## Important

- [ ] **I-1.** Route schemas use `z.object({}).passthrough()` — bypasses Fastify validation. `routes.ts:21,36,38,54,98,115,132`. Body errors surface as 500 instead of 400 with structured details. OpenAPI docs are empty. Fix: replace with actual Zod schemas (body + response), remove redundant `.parse()` calls in controller.
- [ ] **I-2.** Username conflicts cause 500 instead of skip. `sync.service.ts:291-305` only checks email conflict, not username. A non-LDAP user with same username triggers P2002 error. Fix: check both `email` and `username` in conflict lookup. Add test.
- [ ] **I-3.** Sync mutex leaked across vitest runs — test brittleness. `sync.service.test.ts:167-199`. If assertion fails mid-test, `syncInProgress` stays true for rest of file. Fix: wrap in try/finally to always resolve the blocker, or use `vi.resetModules()` in afterEach.
- [ ] **I-4.** `runSync` writes misleading detail on early failures. `sync.service.ts:117` — error detail has `username: ""` regardless of failure phase (bind, search, config, decrypt). Fix: add `phase` field to detail object (e.g., `"bind"`, `"search"`, `"config"`).
- [ ] **I-5.** `ENCRYPTION_SECRET` validation is lazy — yields poor admin UX. `env.ts:37` is optional, but saving LDAP config without it causes 500. Fix: check `ENCRYPTION_SECRET` at config save time in controller, throw `ValidationError` with actionable message. Surface in `GET /admin/ldap/status` as warning.
- [ ] **I-6.** `appUrl` field undocumented in spec, silently degrades. `schema.prisma:407` + `sync.service.ts:341`. When null, welcome email is silently skipped — users stranded with no password. Fix: make `appUrl` required when `enabled=true` (Zod refinement at upsert), update spec.
- [ ] **I-7.** Sync deactivation runs N serial updates. `sync.service.ts:163-180`. Each deactivation is separate DB roundtrip. Fix: use `prisma.user.updateMany` with `{ id: { in: ids } }` for batch deactivation.
- [ ] **I-8.** `isActive` change double-counted in stats. `sync.service.ts:256-277`. Reactivation + attribute change increments both `reactivated` and `updated`. Fix: when `isReactivation`, don't also increment `updated`.
- [ ] **I-9.** Stale `running` sync logs after crash/restart. `sync.service.ts:61`. No recovery on boot for orphaned `running` rows. Fix: in `initSchedulerOnBoot`, mark any `status === "running"` rows older than 5 min as `error` with detail `"Sync interrupted by server restart"`.
- [ ] **I-10.** Integration tests document broken validation as expected behavior. `ldap.integration.test.ts:438-451,505-517,519-530`. Tests assert 500 for missing fields ("raw ZodError from controller parse"). Fix: after I-1, update these tests to expect 400 with structured error bodies.

## Minor

- [ ] **M-1.** IV length is 16 bytes — non-standard for GCM. `encryption.ts:4`. NIST recommends 12-byte IV. Fix: change `IV_LENGTH = 12`. Existing encrypted data still decrypts (IV stored per ciphertext).
- [ ] **M-2.** `LdapConfig.findFirst` with no single-row enforcement. `config.repository.ts:5`. Multiple rows possible via manual DB edit. Fix: use singleton pattern with fixed `id = "singleton"` in upsert, or document the assumption.
- [ ] **M-3.** `LdapClient` throws plain `Error`, not `AppError`. `ldap.client.ts:39` — `throw new Error("LDAP client not connected")`. Surfaces as generic 500. Fix: use `AppError` subclass with proper error code.
- [ ] **M-4.** Knip entry-point trick obscures actual usage. `knip.json:11-15`. Files listed as entry points to silence Knip when they should be reachable transitively. Fix: investigate if removing them triggers false positives; if so, add comment explaining why.
- [ ] **M-5.** `sendLdapWelcomeEmail` HTML body has no escaping. `email/service.ts:183-207`. `appName`, `fromName`, `fromEmail` interpolated raw. Fix: escape with HTML-escape helper.
- [ ] **M-6.** `parseDisplayName` doesn't handle "Last, First" AD format. `sync.service.ts:370-382`. `parseDisplayName("Doe, John")` → `firstName: "Doe,"`, `lastName: "John"`. Fix: detect comma-separated format and swap.
- [ ] **M-7.** `LdapConfig.appUrl` not validated on read path. `controller.ts:70` + `dto.ts:15-20`. Malformed data from manual DB edit returned untouched. Fix: defensive URL validation on read.
- [ ] **M-8.** Test fixture noise — `defaultLog` redefined inline 6+ times. `ldap.integration.test.ts`. Fix: extract `makeLog(overrides)` helper.
- [ ] **M-9.** `searchSyncGroupMembers` uses case-sensitive attribute lookup. `ldap.client.ts:64`. AD may return attributes with different casing. Fix: build case-insensitive lookup over entry keys.
- [ ] **M-10.** Password reset tokens stored in plaintext (pre-existing). `sync.service.ts:348` follows existing pattern. Not introduced by this PR but worth noting. Fix: consider hashing tokens (separate tech debt item if needed).
