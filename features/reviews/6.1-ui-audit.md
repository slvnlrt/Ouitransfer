## Critical

### C-1 — Icon Picker imports ALL react-icons packs eagerly
**File:** `components/ui/icon-picker.tsx:6-36`
**Issue:** Statically imports all 31 react-icons packs at module level (~50,000+ icons into client bundle). The adjacent `dynamic-icon.tsx` already demonstrates the correct lazy-loading pattern.
**Fix:** Build an icon name list without importing actual components; lazy-load only visible icons.

### C-2 — Icon Picker DOM manipulation at module scope
**File:** `components/ui/icon-picker.tsx:53-60`
**Issue:** Creates a DOM element imperatively on import (`document.createElement("iconPicker.style")` — also wrong element name, should be `"style"`). Anti-pattern in Next.js, breaks hydration expectations, potentially CSP-unfriendly.
**Fix:** Use Tailwind arbitrary values (`grid-cols-[repeat(16,1fr)]`) or a CSS module.

### C-3 — Duplicate `<main id="main-content">` landmarks
**File:** `app/(shares)/s/[alias]/page.tsx:44`, `app/(shares)/r/[alias]/components/default-layout.tsx:148`
**Issue:** Root layout already wraps all children in `<main id="main-content">`. Public share pages render additional `<main id="main-content">`, creating duplicate IDs and nested landmarks — WCAG violation.
**Fix:** Remove the inner `<main>` from share pages; use `<section>` or `<div>` instead.

### C-4 — OAuth callback sets token via document.cookie
**File:** `app/auth/callback/page.tsx:56`
**Issue:** Sets auth token via client-side `document.cookie`, bypassing httpOnly/secure cookie requirements. Contradicts the security model (JWT in httpOnly signed cookie) and exposes token to XSS.
**Fix:** OAuth callback should redirect through a server endpoint that sets the httpOnly cookie.

### C-5 — OAuth callback hardcoded English error messages
**File:** `app/auth/callback/page.tsx:24-47`
**Issue:** User-visible error strings ("Authentication failed", "OAuth authentication failed") bypass `useTranslations()` even though `t` is available in scope.
**Fix:** Use translation keys for all user-facing messages.

## Important

### I-1 — Hardcoded colors throughout (design system bypass)
**Files:** 52+ instances across `reverse-shares/components/`, `dashboard/components/`, `components/ui/tags-input.tsx`, `components/general/recipient-selector.tsx`, `app/reset-password/`, `app/forgot-password/`
**Issue:** Widespread use of `text-gray-*`, `bg-gray-*`, `bg-white`, `text-white`, `bg-slate-*`, `text-green-600`, `text-blue-600`, `border-default-200` (non-existent token, likely NextUI remnant) instead of semantic tokens (`text-muted-foreground`, `bg-muted`, `bg-card`, `border-border`, `text-accent-foreground`).
**Impact:** Breaks theming, dark mode inconsistencies, blocks redesign.
**Fix:** Replace all hardcoded palette colors with semantic design tokens.

### I-2 — Hardcoded English strings in toasts/UI
**Files:** `hooks/use-drag-drop.ts:247-251`, `hooks/useUppyUpload.ts:558`, `app/files/page.tsx:245-248`, `app/users-management/components/generate-invite-link-modal.tsx:62`, `app/login/components/multi-provider-buttons.tsx:22`
**Issue:** User-facing toast messages and error strings bypass i18n.
**Fix:** Add translation keys and use `t()` for all user-visible text.

### I-3 — Two competing layout patterns
**Files:** Multiple pages
**Issue:** `dashboard`, `files`, `customization` use `<FileManagerLayout>` (Navbar + sidebar). Other pages (`profile`, `settings`, `users-management`, `shares`, `reverse-shares`) manually compose `<Navbar>` + container div + `<DefaultFooter>` — repeating 5-6 lines of identical boilerplate.
**Fix:** Unify into a single configurable layout component (e.g., `<AppLayout sidebar={true|false}>`).

### I-4 — God components: SharesTable inline editing
**File:** `components/tables/shares-table.tsx:67-148` (568 lines total)
**Issue:** Implements its own inline-edit state management instead of using the extracted `useEditableItem` hook that `FilesTable` uses. Same pattern in two forms.
**Fix:** Refactor `SharesTable` to use `useEditableItem`.

### I-5 — God component: share-details-modal (574 lines)
**File:** `components/modals/share-details-modal.tsx`
**Issue:** Manages inline editing, QR generation/download, link operations, date formatting, and renders 4 sub-modals. QR download logic (lines 200-238) is pure utility code mixed with UI.
**Fix:** Extract QR download utility; consider splitting the modal into tab-based sub-components.

### I-6 — God hook: use-enhanced-file-manager (477 lines)
**File:** `hooks/use-enhanced-file-manager.ts`
**Issue:** 20+ state variables and handlers covering move, rename, delete, selection, clipboard. Parameter list smell.
**Fix:** Decompose into focused hooks (`useFileMove`, `useFileRename`, etc.) composed together.

### I-7 — God hook: use-share-manager (385 lines)
**File:** `hooks/use-share-manager.ts`
**Issue:** 10 state values, 15+ handlers for delete, edit, download, recipients, links, notifications.
**Fix:** Decompose into focused hooks.

### I-8 — God hook: use-public-share (603 lines)
**File:** `app/(shares)/s/[alias]/hooks/use-public-share.ts`
**Issue:** 3 nearly-identical `getFolderFilesWithPath` helper functions (recursive folder traversal). Same logic duplicated in `files/page.tsx:109-129` — 4 copies total.
**Fix:** Extract shared `getFolderFilesWithPath` utility.

### I-9 — Oversized reverse-share modals
**Files:** `reverse-shares/components/edit-reverse-share-modal.tsx` (756 lines), `create-reverse-share-modal.tsx` (632 lines), `received-files-modal.tsx` (546 lines), `reverse-share-card.tsx` (546 lines)
**Issue:** Massive modal components that should be split into logical sub-components (form steps, sections).
**Fix:** Extract form sections into sub-components; share common form logic.

### I-10 — Duplicated upload orchestration
**Files:** `components/general/global-drop-zone.tsx`, `components/modals/upload-file-modal.tsx`
**Issue:** Both configure `useUppyUpload` with identical callbacks (`onValidate`, `onBeforeUpload`, `getPresignedUrl`, `onAfterUpload`).
**Fix:** Extract shared upload config factory.

### I-11 — Duplicated copy-to-clipboard pattern
**Files:** `components/files/embed-code-display.tsx`, `components/files/media-embed-link.tsx`, `components/modals/share-details-modal.tsx`
**Issue:** Identical clipboard state + timeout pattern reimplemented in 3+ places.
**Fix:** Extract `useCopyToClipboard` hook.

### I-12 — Duplicated status icon / file icon helpers
**Files:** `components/modals/upload-file-modal.tsx:247-262`, `components/general/global-drop-zone.tsx:244-255`
**Issue:** `getStatusIcon` / `renderFileIcon` duplicated between upload components.
**Fix:** Extract to shared `ui/status-icon.tsx`.

### I-13 — Every page is "use client" — no server components
**Files:** All 15+ page files
**Issue:** Every page is marked `"use client"`. Static content (headers, empty states, structural markup) that could be server-rendered is sent as JS. Pages like `customization/page.tsx` (34 lines, renders 5 forms) could have server-rendered shells with client islands.
**Fix:** Evaluate which pages can have server-rendered shells wrapping client islands.

### I-14 — No per-route loading.tsx or error.tsx
**Files:** All authenticated routes
**Issue:** Only root has `loading.tsx`. Authenticated routes rely on manual `if (isLoading) return <LoadingScreen />` — doesn't leverage Suspense boundaries, full page JS must load before showing any loading state.
**Fix:** Add `loading.tsx` to key route groups.

### I-15 — Legacy forwardRef pattern in shadcn components
**Files:** `components/ui/tabs.tsx:10-53`, `components/ui/textarea.tsx:9-21`
**Issue:** These two components use the React 18 `forwardRef` + `const` + `displayName` pattern while all other shadcn/ui components use modern React 19 function declarations (ref as prop).
**Fix:** Migrate to React 19 pattern for consistency.

### I-16 — Drag ghost uses imperative DOM with hardcoded inline styles
**File:** `hooks/use-drag-drop.ts:54-133`
**Issue:** `createDragGhost` builds a drag preview with ~30 hardcoded inline style assignments (px values, colors, shadows). Bypasses design system entirely.
**Fix:** Extract to a CSS class or use a pre-rendered hidden React component.

### I-17 — Redundant custom line-clamp utilities
**File:** `app/globals.css:127-146`
**Issue:** Custom `line-clamp-1/2/3` classes defined manually but Tailwind 4 includes these natively.
**Fix:** Remove the custom definitions.

### I-18 — useUppyUpload naming inconsistency
**File:** `hooks/useUppyUpload.ts`
**Issue:** Only hook file using camelCase. All others use kebab-case (`use-*.ts`).
**Fix:** Rename to `use-uppy-upload.ts`.

### I-19 — Duplicate getAppInfo/getBaseUrl helpers
**Files:** `app/(shares)/r/[alias]/layout.tsx`, `app/(shares)/s/[alias]/layout.tsx`
**Issue:** Both layouts define identical async helper functions.
**Fix:** Extract to shared utility.

### I-20 — Misnamed layout functions
**Files:** `app/(shares)/s/[alias]/layout.tsx:110` (named `DashboardLayout`), `app/(shares)/shares/layout.tsx:16` (named `UsersManagementLayout`)
**Issue:** Function names don't match their actual purpose.

### I-21 — Wrong metadata title in users-management

## Cross-Cutting Patterns

### Positive Patterns
- Consistent `cn()` usage for class merging
- Good RTL support via logical properties
- TanStack Query used consistently for server state
- `@/` path alias used almost everywhere
- Logger utility used instead of console.*
- motion animations target GPU-composited properties (no performance concerns)

### Systemic Issues to Address in 6.2
1. **Hardcoded colors** — biggest blocker for redesign (I-1, 52+ instances)
2. **God hooks/components** — 5 files over 500 lines need decomposition
3. **Duplicated patterns** — copy-to-clipboard, upload config, folder traversal, status icons
4. **i18n gaps** — hardcoded English in toasts, sr-only, empty states
5. **Layout inconsistency** — two competing page shell patterns
6. **Missing "use client"** and server component opportunities

### Extraction Opportunities (for 6.2)
1. `useCopyToClipboard` hook
2. `createUploadConfig` factory

4. `getFolderFilesWithPath` utility
5. `<AppLayout>` unified layout component
