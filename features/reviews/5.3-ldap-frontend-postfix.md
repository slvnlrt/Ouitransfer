## Minor

- [ ] **PF-F-M-1.** `setTimeout` in `handleCloseDetail` not stored — modal close race condition. `hooks/use-ldap-sync.ts:98-101` — `setTimeout(() => setSelectedLog(null), 200)` is called without storing the handle. If the user closes a detail modal and opens another within 200 ms, the stale timer fires and clears `selectedLog` while the user is reading the new modal. Fix: store the timeout in a `useRef<ReturnType<typeof setTimeout> | null>`, clear it in `handleViewDetail` and on unmount:
  ```ts
  const closeTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  const handleViewDetail = (log: LdapSyncLog) => {
    if (closeTimerRef.current) clearTimeout(closeTimerRef.current);
    setSelectedLog(log);
    setIsDetailOpen(true);
  };

  const handleCloseDetail = () => {
    setIsDetailOpen(false);
    closeTimerRef.current = setTimeout(() => setSelectedLog(null), 200);
  };
  ```
  Clear `closeTimerRef.current` in the `useEffect` cleanup.

- [ ] **PF-F-M-2.** TLS switches layout uses a `pt-6` hack. `components/ldap-config-form.tsx:73` — the `pt-6` padding-top is added to vertically align the TLS toggles with the server URL input on the left. This is fragile: any change to input height breaks the alignment. Fix: use an empty `<Label>&nbsp;</Label>` placeholder in the right column's `<div className="space-y-2">`, or wrap both columns in a CSS grid with aligned rows, so spacing is structural rather than manual.

- [ ] **PF-F-M-3.** Form schema doesn't enforce `appUrl` required-when-enabled at the frontend. `hooks/use-ldap-config.ts:ldapConfigFormSchema` — the schema accepts an empty `appUrl` even when `enabled: true`. The server enforces this and returns a 400, but the user only sees a generic error after submission. Fix: add a `.refine()` to the schema:
  ```ts
  .refine((data) => !data.enabled || (data.appUrl && data.appUrl.length > 0), {
    message: "Application URL is required when LDAP is enabled",
    path: ["appUrl"],
  });
  ```
  Similarly, `bindPassword` could be required when there is no existing config (`configQuery.data?.configured === false`), though this requires passing context into the schema — acceptable to leave as server-side only.
