## Minor

- [x] **PF-F-M-1.** `setTimeout` in `handleCloseDetail` not stored — modal close race condition. `hooks/use-ldap-sync.ts:98-101` — `setTimeout(() => setSelectedLog(null), 200)` is called without storing the handle. If the user closes a detail modal and opens another within 200 ms, the stale timer fires and clears `selectedLog` while the user is reading the new modal. Fix: store the timeout in a `useRef<ReturnType<typeof setTimeout> | null>`, clear it in `handleViewDetail` and on unmount:
  ```ts
  const closeTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  const handleViewDetail = (log: LdapSyncLog) => {
    if (closeTimerRef.current) clearTimeout(closeTimerRef.current);
    setSelectedLog(log);
    setIsDetailOpen(true);
  };

  const handleCloseDetail = () => {
    setIsDetailOpen(false);
    closeTimerRef.current = setTimeout(() => setSelectedLog(null), 200);
  };
  ```
  Clear `closeTimerRef.current` in the `useEffect` cleanup.

- [x] **PF-F-M-2.** TLS switches layout uses a `pt-6` hack. `components/ldap-config-form.tsx:73` — the `pt-6` padding-top is added to vertically align the TLS toggles with the server URL input on the left. This is fragile: any change to input height breaks the alignment. Fix: use an empty `<Label>&nbsp;</Label>` placeholder in the right column's `<div className="space-y-2">`, or wrap both columns in a CSS grid with aligned rows, so spacing is structural rather than manual.

- [x] **PF-F-M-3.** Form schema doesn't enforce `appUrl` required-when-enabled at the frontend. `hooks/use-ldap-config.ts:ldapConfigFormSchema` — the schema accepts an empty `appUrl` even when `enabled: true`. The server enforces this and returns a 400, but the user only sees a generic error after submission. Fix: add a `.refine()` to the schema:
  ```ts
  .refine((data) => !data.enabled || (data.appUrl && data.appUrl.length > 0), {
    message: "Application URL is required when LDAP is enabled",
    path: ["appUrl"],
  });
  ```
- [x] **PF-F-M-4.** Form schema doesn't enforce `bindPassword` required-when-new. `hooks/use-ldap-config.ts:ldapConfigFormSchema` — when configuring LDAP for the first time (`configQuery.data?.configured === false`), `bindPassword` is required but the frontend schema doesn't enforce it. The server returns a 400, but the user only sees a generic error. Fix: since this requires runtime context (`configured` state), use a `.superRefine()` that receives context, or validate in the submit handler before calling the mutation. Either way, surface a field-level error on `bindPassword` when it's empty and no config exists yet.

- [x] **PF-F-M-5.** `formatRelativeTime` doesn't guard against invalid `dateStr`. `utils/format-relative-time.ts` — if `dateStr` is an invalid date string, `new Date(dateStr).getTime()` returns `NaN`, which propagates through the arithmetic and results in `"NaN d ago"` displayed in the UI. Fix: add a `Number.isFinite` check after computing the diff, and return a fallback string (e.g., `t("ldap.time.justNow")` or `"—"`) when the input is invalid.

- [x] **PF-F-M-6.** In-flight poll request after `stopPolling()`. In both `use-ldap-sync.ts` and `users-management/page.tsx` — when `stopPolling()` clears the interval, a fetch that was already in-flight will still resolve and call `invalidateQueries`. This is harmless (idempotent), but for correctness add an `isMounted` ref or `isPolling` ref guard so the callback no-ops if polling was stopped. This will naturally be addressed when extracting the shared polling hook (PF-F-I-2).

- [x] **PF-F-M-7.** Pre-existing typo in `en-US.json:2241` — `"userr": "User"`. Should be `"user": "User"`. Check if this key is referenced anywhere; if so, update the reference too. If not, just fix the typo. Also verify the key exists correctly across all 23 locale files.
