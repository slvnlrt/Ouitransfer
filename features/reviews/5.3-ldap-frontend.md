# Review — 5.3 LDAP/AD Sync (Frontend)

## Critical

- [x] **C-1.** Masked bind password sent to Test Connection — always fails on existing config. `hooks/use-ldap-config.ts:59,87-101`. Form populates `bindPassword` from server response which is `"••••••••"` (mask). Clicking "Test Connection" sends the mask literal to the server → LDAP bind fails with "Invalid credentials". Fix: initialize `bindPassword` to `""` in form reset, show placeholder "Leave blank to keep existing". Server test endpoint should use stored (encrypted) password when request password is empty. **Fixed:** `b2f3083` — `bindPassword` always initialized to empty string. Test button disabled when password field empty.
- [x] **C-2.** No form validation — empty submissions hit backend with generic error toasts. `components/ldap-config-form.tsx:59,69,89,98`. No Zod resolver, no `required` attributes. All fields optional at HTML level. Fix: add Zod schema + `zodResolver`, mirror `group-form-modal.tsx` pattern. Required fields: `serverUrl`, `bindDn`, `searchBase`, `syncGroupDn`, attribute fields, `syncIntervalMinutes` (15-10080). `bindPassword` required only when no existing config. **Fixed:** `b2f3083` — Added Zod schema with zodResolver. Field errors displayed below each input.

## Important

- [x] **I-1.** Sync error toast shows raw axios message. `hooks/use-ldap-sync.ts:46-49`. `error.message` yields "Request failed with status code 409" instead of user-friendly text. Fix: extract `error.response?.data?.message` or `error.response?.data?.error`, fall back to i18n key. **Fixed:** `bcbe77b` — Both hooks use `parseApiError()` to extract structured error messages.
- [x] **I-2.** LDAP page missing breadcrumb/icon header — inconsistent with other admin pages. `page.tsx:52-55`. Users/Groups management pages use icon + h1 + Separator + Breadcrumb. Fix: create `ldap-header.tsx` matching `users-header.tsx`/`groups-header.tsx` pattern. **Fixed:** `bcbe77b` — Created `ldap-header.tsx` with breadcrumbs matching admin page pattern.
- [x] **I-3.** Hardcoded English in `formatRelativeTime`. `components/ldap-sync-operations.tsx:36-44`. "just now", "5m ago", "2h ago" are never translated. Fix: add i18n keys (`ldap.time.justNow`, `ldap.time.minutesAgo`, etc.) and use `useTranslations`, or use `next-intl`'s `useFormatter().relativeTime()`. **Fixed:** `bcbe77b` — Extracted to shared `format-relative-time.ts` utility using i18n keys.
- [x] **I-4.** User list doesn't refresh after async sync completes. `users-management/page.tsx:52-62`. Sync mutation invalidates `queryKeys.users.all` immediately but sync runs asynchronously on backend. Users won't see new LDAP users until manual refresh. Fix: poll `getLdapStatus` or `getLdapSyncLogDetail(logId)` until `syncInProgress === false`, then re-invalidate `queryKeys.users.all`. **Fixed:** `bcbe77b` — Both sync locations poll every 3s until syncInProgress=false, then invalidate user queries. Cleanup on unmount.
- [x] **I-5.** "Source" column header case mismatch. `messages/en-US.json:2233`. Existing headers are UPPERCASE ("USER", "EMAIL", "STATUS", "ROLE", "ACTIONS"). New header is "Source" (title case). Fix: change to "SOURCE" in en-US.json. **Fixed:** `bcbe77b` — Changed to "SOURCE".
- [x] **I-6.** Test Connection result lacks ARIA live region. `components/ldap-config-form.tsx:170-190`. Async result not announced to screen readers. Fix: add `role="status"` and `aria-live="polite"` to result container. **Fixed:** `bcbe77b` — Added `role="status"` and `aria-live="polite"`.
- [x] **I-7.** Users page "Last sync" uses absolute date, spec says relative. `users-management/page.tsx:82-87`. Shows `toLocaleString()` instead of "2h ago" format. Fix: reuse relative-time formatter (after I-3 is applied). **Fixed:** `bcbe77b` — Uses shared `formatRelativeTime()` utility.
