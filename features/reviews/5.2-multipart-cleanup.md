# Review — Incomplete Multipart Upload Cleanup (PR #19, `7dc9404..b2f9df6`)

## Summary

Extends the Phase A orphan sweep (`sweepOrphans`) with a third reconciliation
phase that aborts abandoned/incomplete multipart uploads (invisible to
`ListObjectsV2`), and adds an always-on `AbortIncompleteMultipartUpload`
bucket-lifecycle backstop for INTERNAL storage applied at `ensureBucket()`.
Both are gated/parameterised by the existing `autoCleanupOrphansEnabled` +
`autoCleanupOrphanMinAgeHours` config (lifecycle backstop is unconditional but
internal-only). New audit action `ORPHAN_MULTIPART_ABORTED` with 23-locale label
parity. Docs updated EN + FR.

Reviewed: 4 commits, 36 files. Server type-check passes. Full server suite
passes (1475/1475). `knip` clean.

## Verdict

**APPROVE.** The change is correct, safe, well-tested, and well-documented. No
Critical or Important findings. The two safety-critical properties — the
abort-age boundary and the external-bucket protection — are correctly
implemented and explicitly asserted in tests. Two Minor observations below are
informational; neither requires a code change.

## Confirmed-clean dimensions

- **Abort-age boundary (safety, most important).** `service.ts:1332`
  `if (upload.initiated >= cutoff) continue;` — an upload initiated *at* or
  *after* the cutoff is protected (skipped); only strictly-older uploads are
  aborted. `cutoff = now - minAgeHours`. In-flight uploads younger than
  `minAgeHours` (default 24h) are never touched. Directly asserted by the
  boundary test (`service.test.ts`: "NEVER aborts an upload younger than the
  min-age cutoff (boundary)") using `cutoff+1` (protected) and `cutoff-1`
  (aborted).
- **Epoch fallback risk.** `s3-storage.provider.ts:438` defaults a missing
  `Initiated` to `new Date(0)` → treated as *old* → eligible for abort. This is
  the documented, intentional choice for a malformed entry. In practice
  S3/RustFS always return `Initiated` for `ListMultipartUploads`; the fallback
  only fires on a non-conformant response. Risk judged low and acceptable (a
  truly fieldless entry is itself malformed) — see Minor M-1 for the residual
  edge.
- **Dry-run.** `service.ts:1334-1342` — dry-run pushes a candidate and increments
  the counter but calls neither `abortMultipartUpload` nor `logAuditEvent`.
  Asserted ("multipart dryRun: lists candidates but aborts nothing and emits no
  audit").
- **Per-item fault tolerance.** `service.ts:1356-1362` — each abort is wrapped in
  try/catch; a failure increments `errors` and logs, never aborts the loop.
  Asserted ("tolerates a single abort failure without aborting the rest").
- **Idempotent abort.** `abortMultipartUpload` issues `AbortMultipartUploadCommand`;
  aborting an already-gone upload is a no-op/benign error swallowed by the
  per-item catch.
- **External-bucket protection (lifecycle backstop).** `storage.config.ts:224`
  `if (!isExternalS3) { await applyIncompleteMultipartLifecycle(...) }` — the
  lifecycle PUT is NEVER issued against an external/admin bucket. Asserted ("does
  NOT apply the lifecycle rule for EXTERNAL S3").
- **Lifecycle rule scope.** `storage.config.ts:155-170` — the rule contains ONLY
  `AbortIncompleteMultipartUpload` with `DaysAfterInitiation: 7`; no
  object-expiration/transition rule that could delete real objects. Whole-bucket
  via empty-prefix filter. `DaysAfterInitiation` value asserted in test.
- **Best-effort lifecycle.** `storage.config.ts:171-178` — try/catch logs a
  warning and returns; cannot throw → cannot crash boot. Asserted ("does not
  crash boot when the lifecycle rule is rejected").
- **Pagination termination.** `s3-storage.provider.ts:421-450` — markers fed back
  only while `IsTruncated`, both cleared otherwise; loop condition
  `keyMarker !== undefined || uploadIdMarker !== undefined`. Even a
  non-conformant `IsTruncated: true` with undefined markers terminates (no
  infinite loop). Pagination, empty-result, prefix-forwarding, and
  malformed-entry-skip all asserted.
- **Interface conformance.** `listMultipartUploads` added to `StorageProvider`
  (`types/storage.ts`); `S3StorageProvider` is the only implementer.
- **Scheduler integration.** Third phase lives inside `sweepOrphans`, so the
  existing scheduler gate (`cleanup.scheduler.ts:182`) and CLI wrapper pick it up
  with no new wiring. `multipartAborted` threaded through the scheduler summary
  type (`cleanup.scheduler.ts:114`) and surfaced via `log.info({ summary })`.
  CLI dry-run prints multipart candidates and totals.
- **Audit + i18n.** `ORPHAN_MULTIPART_ABORTED` added to `AUDIT_ACTIONS`; label
  present in all 23 locale files (verified 23/23).
- **Hygiene.** No `as any`, no dead code, no stale comments. `knip` clean.
  Doc-comments accurate and thorough.

### Minor

- [ ] **[Minor] Epoch fallback would abort a fieldless in-flight upload if a backend ever omits `Initiated`** — `apps/server/src/providers/s3-storage.provider.ts:438` — `initiated: upload.Initiated ?? new Date(0)` treats a missing timestamp as epoch (old → abortable). The brief explicitly accepts this for malformed entries, and conformant S3/RustFS always populate `Initiated`, so the practical risk is near-zero. Documented in both the provider and service doc-comments. No change required; noting only as the single theoretical path where the min-age guard could be bypassed. If ever paranoid, one could skip (protect) entries lacking `Initiated` instead — but that would let genuinely-malformed entries linger forever, which is arguably worse. Current choice is defensible; leave as-is.

- [ ] **[Minor] Lifecycle PUT replaces the whole bucket lifecycle config on internal storage** — `apps/server/src/config/storage.config.ts:153-170` — `PutBucketLifecycleConfigurationCommand` replaces the *entire* lifecycle configuration, not just one rule. For the bundled RustFS internal bucket this is fine: Ouitransfer owns that bucket and sets no other lifecycle rules, and the doc/`Callout` correctly scopes the backstop to internal storage only (external buckets are never touched — confirmed). The only scenario where this would clobber an operator-defined rule is an operator manually adding lifecycle rules to Ouitransfer's *internal* bucket out-of-band, which is unsupported. Acceptable as designed; flagged for awareness. No change required.
