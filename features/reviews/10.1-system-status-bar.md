# 10.1 System Status Bar — Review Findings

## Important

- [x] **I-1: Status derivation client-side overrides server** — `system-status-bar.tsx:504-510`
  Admin view re-derives `overallStatus` from individual check results instead of trusting `healthData.status`. This can produce inconsistencies (e.g., server says "unhealthy" but client shows "degraded"). Fix: use `healthData.status` directly.

- [x] **I-2: Admin duplicate progress bar (dead code)** — `system-status-bar.tsx:345-357`
  "Admin personal quota override" renders a second `CompactProgressBar` using the same `diskSpace` object as the disk space bar above it. This always renders two identical bars when `warningLevel` is defined. Delete this block — `DiskSpaceInfo` doesn't distinguish admin quota from platform disk.

- [x] **I-3: `aria-expanded` discontinuity** — `system-status-bar.tsx:105` vs `454-461`
  Collapsed tab has `aria-expanded={false}` but the collapse button in the expanded panel has no `aria-expanded={true}` or `aria-controls`. Screen readers see a broken disclosure pattern. Fix: add `aria-expanded={true}` + `aria-controls` matching the section's `id`.

- [x] **I-4: No expand/collapse animation** — `system-status-bar.tsx`
  Implemented CSS grid height animation (`grid-template-rows: 0fr → 1fr`) with `transition-[grid-template-rows] duration-300 ease-in-out`. Single sticky wrapper, expanded panel always in DOM with `aria-hidden` when collapsed, overflow-hidden for clean clipping.

- [x] **I-5: 4 queries on every authenticated page** — `use-system-status.ts`
  Implemented conditional polling: 60s when expanded, 5 min (300s) when collapsed. Admin stats query only enabled when expanded AND admin. Hook now accepts `{ isExpanded?: boolean }` options.

- [x] **I-6: Loading skeleton always shows 2 bars** — `system-status-bar.tsx:466-470`
  Admin has 3 sections, user has 2. Always shows 2. Tailor skeleton count by `isAdmin` (3 bars for admin, 2 for user).

- [x] **I-7: Collapse button too far from content** — User feedback
  The collapse button (ChevronUp) is in the top-right title row, far from the content. Move it to center-bottom of the expanded panel as a centered button below the content area.

## Minor

- [x] **M-1: `percentage` label can show >100% but bar caps at 100** — `system-status-bar.tsx:171,174`
  Intentional (exceeded quota shows real %), but add a brief comment.

- [x] **M-2: `progressClassName` uses `Record<string, string>`** — `system-status-bar.tsx:160`
  Too loose. Change to `Record<"none" | "warning" | "critical" | "exceeded", string>`.

- [x] **M-3: `colors!.border` produces `"false"` in template literal** — `system-status-bar.tsx:104`
  `${!isLoading && colors!.border}` evaluates to `"false"` when loading. Use ternary: `${!isLoading ? colors!.border : ""}`. Same at lines 111, 123.

- [x] **M-4: `MetricCell` should use `<dl>/<dt>/<dd>`** — `system-status-bar.tsx:187-194`
  Two stacked `<span>` elements. A `<dl>/<dt>/<dd>` pattern is more semantic for number+label pairs. Optional improvement.

- [x] **M-5: Test mocks `formatStorageSize` — no integration coverage** — `system-status-bar.test.tsx:41-43`
  The utility is tested separately. Note this is acceptable, but add a comment in the test file explaining why.

- [x] **M-6: Shake/pulse on transition not implemented** — Spec line 55
  Spec says "optional stronger animation on state transition." Remove from spec or mark as optional follow-up.

- [x] **M-7: `formatUptime` boundary tests missing** — `system-status-bar.test.tsx:559-607`
  No tests for `seconds = 59` (→ "0m") and `seconds = 60` (→ "1m"). Add these two boundary tests.

- [x] **M-8: `sticky top-16` assumes navbar always 64px** — `file-manager-layout.tsx:38`, `page-layout.tsx:24`
  Add a comment: `{/* Assumes navbar h-16 (64px) */}`.

- [x] **M-9: `React.ReactNode` without React import** — `system-status-bar.tsx:403`
  Works via global JSX types but inconsistent with explicit imports elsewhere. Either add `import type React from "react"` or use `import type { ReactNode } from "react"`.

- [x] **M-10: Redundant `role="region"` spec reference** — Spec line ~114
  `<section aria-label>` already implies `role="region"`. Implementation is correct (no redundant role attr). Update spec to note the intentional semantic equivalent.

- [x] **M-11: `progressClassName` double fallback** — `system-status-bar.tsx:175`
  Outer `?? ""` is technically unreachable with current type but serves as safety. Fine — but tightening the Record type (M-2) makes this truly redundant. Keep the `?? ""` as defensive coding.
