## Task 1: Design Token Migration

**Findings addressed:** I-1 (52+ hardcoded color instances)

**Goal:** Replace all hardcoded Tailwind palette colors with semantic design tokens from the shadcn/ui theme system.

**Files to modify:** ~30+ files across:
- `apps/web/src/app/(shares)/reverse-shares/components/*.tsx`
- `apps/web/src/app/dashboard/components/*.tsx`
- `apps/web/src/components/ui/tags-input.tsx`

- `apps/web/src/app/forgot-password/page.tsx`
- `apps/web/src/components/modals/share-details-modal.tsx`
- Any other file using `text-gray-*`, `bg-gray-*`, `bg-white`, `text-white`, `bg-slate-*`, `text-green-*`, `text-blue-*`, `border-default-*`

**Mapping table:**

| Hardcoded | Semantic replacement |
|-----------|---------------------|
| `text-gray-500`, `text-gray-600` | `text-muted-foreground` |
| `text-gray-700`, `text-gray-800`, `text-gray-900` | `text-foreground` |
| `bg-gray-50`, `bg-gray-100` | `bg-muted` |
| `bg-white` | `bg-background` or `bg-card` |
| `text-white` (on colored bg) | `text-primary-foreground` or `text-accent-foreground` |
| `border-gray-200`, `border-gray-300`, `border-default-200` | `border-border` |
| `bg-slate-300`, `dark:bg-slate-800` | `bg-muted` |
| `text-green-600` (success/stats) | `text-emerald-600 dark:text-emerald-400` (keep explicit for semantic meaning) or define a `--success` token |
| `text-blue-600`, `bg-blue-50` (selection/accent) | `text-accent-foreground`, `bg-accent` |
| `border-blue-200` (selection) | `border-accent` |
| `bg-black/20` | `bg-background/20` or `bg-muted/50` |

**Steps:**

- [ ] **1.1** Search all `.tsx` and `.ts` files in `apps/web/src/` for hardcoded color patterns: `text-gray-`, `bg-gray-`, `text-white`, `bg-white`, `text-slate-`, `bg-slate-`, `border-gray-`, `border-slate-`, `border-default-`, `text-green-`, `text-blue-`, `bg-blue-`, `border-blue-`, `bg-black/`
- [ ] **1.2** Replace each instance using the mapping table. Respect context: a `bg-white` that's a card should be `bg-card`, a `bg-white` that's a page background should be `bg-background`.
- [ ] **1.3** For instances where meaning is semantic (success/error/warning colors), ensure the replacement works in both light and dark mode. Use `text-emerald-600 dark:text-emerald-400` for success, `text-destructive` for errors.
- [ ] **1.4** Run `pnpm --filter web run type-check && pnpm --filter web run build` — verify no issues.
- [ ] **1.5** Visual spot-check: ensure the landing page, dashboard, and share pages render correctly in both light and dark mode.
- [ ] **1.6** Commit: `fix(web): replace hardcoded colors with semantic design tokens`
