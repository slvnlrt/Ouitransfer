# 5.3 LDAP/AD Synchronization — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import and synchronize user accounts from Active Directory into Ouitransfer, with local app passwords, group-based quota mapping, and a dedicated admin UI.

**Architecture:** New `ldap` server module with config/sync repositories, ldapts client wrapper, sync engine with diff logic, and setInterval-based scheduler. Dedicated `/admin/ldap` frontend page with config form, group mapping summary, and sync history. Enhancements to User Management (LDAP badge, sync button) and Settings (LDAP banner).

**Tech Stack:** ldapts (LDAP client), AES-256-GCM (bind password encryption), Prisma (schema), Fastify (routes), React/TanStack Query (frontend), next-intl (i18n)

**Spec:** `features/specs/5.3-ldap.md`

**Deviation from spec:** Uses `setInterval` instead of `node-cron` for scheduling — matches existing codebase pattern (see `server.ts` lines 104-135) and is simpler for "every N minutes" use cases. No new dependency needed.

**Addition to spec:** `appUrl` field added to `LdapConfig` — required for constructing invite email links during scheduled sync (no request context available). If not set, welcome emails are skipped with a warning log.
