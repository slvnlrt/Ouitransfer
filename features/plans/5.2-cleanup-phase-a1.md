# 5.2 Phase A.1 — Unified explicit lifecycle (deactivate → delete) + manual pause

Spec: [`features/specs/5.2-cleanup.md`](../specs/5.2-cleanup.md) — "Phase A.1" section is binding.

Reworks Phase A's share/reverse-share cleanup into an explicit two-phase lifecycle
(`active → deactivated → deleted`), uniform across triggers (expiration / maxViews / manual),
with a single grace measured from `deactivatedAt`, manual pause/resume, and manual pauses never
auto-deleted. Reuses Phase A's delete helpers + notification types. Same quality bar (zero tech
debt, full suites, integration tests for security flows). Subagents dispatched **sequentially**.

## Batch 1 — Schema + lifecycle constants + migration

- `Share`: add `isActive Boolean @default(true)`, `deactivatedAt DateTime?`, `deactivationReason String?`.
- `ReverseShare`: add `deactivatedAt DateTime?`, `deactivationReason String?` (already has `isActive`).
- Shared lifecycle constant/type `DeactivationReason = "expired" | "max_views" | "manual"` (server module or `@ouitransfer/shared`; pick the spot consistent with existing enums).
- `prisma migrate dev --name share_lifecycle`. Backfill is implicit (`isActive` defaults true; existing rows get NULL deactivatedAt/reason). Regenerate client.
- Unit-test touch-ups only (no behavior yet). Verify type-check + full server suite green.

## Batch 2 — Read-time gating + deactivation/reactivation transitions (services)

- **share/service.ts `getShare`**: gate on `isActive` first (block with reason → `OWNER_INACTIVE` already exists for owner; add/choose a code for share-level deactivation, e.g. reuse `SHARE_EXPIRED`/`MAX_VIEWS_REACHED` by reason, or a `SHARE_INACTIVE` code — keep owner-self access exempt as today). Keep defensive expiry/maxViews checks (a share that expires between sweeps must still block). When the atomic maxViews increment hits the limit, set `isActive=false, deactivatedAt=now, deactivationReason="max_views"` in the same path that already fires `share_max_views_reached`.
- **reverse-share**: access/upload paths already gate `isActive`; when expiry is detected set `deactivatedAt`/`reason="expired"`. Keep the `assertOwnerActive` (A6) gate intact.
- **Manual pause/resume (service methods)** for shares: `pauseShare(id, ownerId)` (isActive=false, deactivatedAt=now, reason="manual") and `resumeShare(id, ownerId)` (isActive=true, clear deactivatedAt/reason, reset `notifiedForPendingDeletion`; refuse/no-op-revive if still expired/maxed — read-time stays blocked). Align the existing reverse-share isActive toggle to set/clear `deactivatedAt`/`reason` consistently.
- **Reactivation on update**: extending `expiration` / raising `maxViews` clears `isActive`/`deactivatedAt`/`reason` + resets notified flags (extend the existing notified-flag reset logic).
- Audit: `SHARE_DEACTIVATED`/`SHARE_REACTIVATED` (+ reverse-share variants), reason in metadata.
- Tests: `app.inject()` integration for read-time gating by reason, pause/resume round-trip, reactivation-on-extend, maxViews-sets-deactivation. Service unit tests.

## Batch 3 — Scheduler sweeps (rework cleanup service)

- Replace `cleanupExpiredShares` + `cleanupMaxViewsShares` with:
  - **`deactivateEndedShares()`** — active shares where `expiration < now` (reason `expired`, deactivatedAt=expiration) or `maxViews` reached (reason `max_views`) → set inactive + send the deactivation notice (`share_expired` / `share_max_views_reached`), once (reuse existing `notifiedForExpired`/`notifiedForMaxViews` flags). Also upgrades a `manual` pause to `expired` when expiration has passed.
  - **`deleteDeactivatedShares({ graceDays, notifyDaysBefore })`** — `isActive=false AND reason ∈ {expired,max_views} AND deactivatedAt < now-grace` → warn (`share_pending_deletion`, `notifiedForPendingDeletion`) then delete via `deleteShareLink` + audit `SHARE_AUTO_DELETED` + `share_auto_deleted`.
- Same split for reverse shares (`deactivateEndedReverseShares` + `deleteDeactivatedReverseShares` using `deleteReverseShareWithStorage`).
- Retire `cleanupExpiredReverseShares`. Keep `purgeUserContent`, `cleanupDeactivatedAccounts`, `sweepOrphans` unchanged.
- **cleanup.scheduler.ts**: call the deactivation sweep then the deletion sweep (both gated by `autoCleanupEnabled`). Drop the `maxViewsCleanupDays` read; deletion sweep uses `autoCleanupGracePeriodDays` + `autoCleanupNotifyDaysBefore`.
- Tests: deactivation sweep (expiry + maxViews + manual→expired upgrade, notify-once), deletion sweep (grace boundary from deactivatedAt, manual excluded, warn-once), reverse-share equivalents. Update existing cleanup tests to the new functions/signatures.

## Batch 4 — Endpoints + frontend (pause/resume + deactivated UI)

- Frontend: on the share card/list show a **deactivated/paused** state with a reason badge (`expired` / `view limit` / `paused`), a **resume** action for manual pauses, a **renew/extend** affordance for expired, and a manual **pause** toggle — mirroring the existing reverse-share `clickToActivate/clickToDeactivate` toggle. Wire the API client + query invalidation.
- i18n for the new labels/badges in all 23 locales (en/fr authored, EN replicas elsewhere per convention).
- Web tests + type-check + full web suite green.
